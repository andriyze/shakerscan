# ShakerScan 0.8.9

ShakerScan 0.8.9 carries forward the unpublished 0.8.8 Fleet route-lifecycle fix and hardens clean
release builds against bounded transient registry failures.

## Fixes

- Broker workers no longer receive an opaque HTTP 500 when the final acknowledgement on an empty
  placement route removes its Redis Stream consumer group while another worker is already polling
  that route.
- Both abandoned-lease reclaim and fresh-work long polling recognize only Redis's specific
  `NOGROUP` lifecycle response, refresh surviving groups, discard an already-pruned route, and return
  bounded no-work. Every unrelated Redis failure remains visible.
- Release validation retries clean scanner, API, signer, and Firecracker guest builds up to four
  times with bounded linear backoff. Successful layers remain cached between attempts, so an 821 MB
  base-image pull interrupted by a registry connection reset resumes instead of discarding the
  release after one transient failure. Exhausted retries still stop all publication.
- Managed HTTPS documentation calls out the persistent Caddy certificate volumes and the public-CA
  consequences of deleting them during repeated destructive lab rebuilds.

## Validation

The release candidate must pass the full backend and UI suites, production builds, generated
inventory, named release gates, dependency audits, installer and upgrade smokes, and published-image
acceptance. Deterministic tests cover both Redis lease-race positions, unrelated-error propagation,
and the retry helper's success, retry, final-status, and invalid-configuration contracts. The exact
prune-while-polling timing also passed 40 forced iterations against real Redis 7.4.

## Promotion status

The four 0.8.9 multi-architecture images were published and independently matched their `latest`
manifests. The hosted stable channel was deliberately left at 0.8.7 after a subsequent whole-product
audit found that installed agent and MCP launchers still assumed loopback on a Tailscale-only remote
bind. That correction is carried by 0.8.10; new users should install the stable channel rather than
pinning 0.8.9.

## Supported deployment boundary

ShakerScan 0.8.9 remains a trusted-operator, self-hosted release. Localhost is the default; remote
operator access belongs behind Tailscale, a VPN, firewall, or authenticated reverse proxy. Fleet
production support remains limited to the outbound-only HTTPS broker. Fleet WireGuard and AI Gate
remain preview surfaces, and the Model Intake Firecracker tier remains an explicit AMD64 Linux/KVM
host installation.
