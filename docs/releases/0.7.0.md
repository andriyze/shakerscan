# ShakerScan 0.7.0

ShakerScan 0.7.0 is a major scanner-engine and operator-workflow release for trusted users running
locally or on a private VPS. It substantially expands proof-first DAST, authenticated testing,
parallel coverage, Continuous ASM, and keyless AI-driven investigation while hardening installation,
upgrades, safety limits, and release reproducibility.

## Highlights

### Proof-first DAST

- Stronger deterministic proof boundaries for SQL injection, XSS, authenticated access control,
  BOLA/IDOR, mass assignment, JWT checks, finding severity, and attack-chain presentation.
- High-impact findings distinguish verified proof from suspected or unverified signals. AI judgment
  cannot manufacture deterministic proof or upgrade a weak result into a verified finding.
- Execution and coverage receipts distinguish completed, skipped, blocked, cancelled, failed,
  partial, and unobserved work instead of treating missing telemetry as clean coverage.
- Expanded registry-backed detector dispatch, attempt telemetry, request budgets, and cooperative
  cancellation across release-critical active paths. Remaining legacy registry gaps are documented
  and are not presented as fully authoritative coverage.

### Authenticated applications and APIs

- Authentication propagates through browser discovery, templates, SQLi/XSS tooling, and custom
  checks, with session refresh support for long scans.
- Two-user BOLA/IDOR testing records redacted identity and accepted-auth receipts. A verified
  cross-user result requires distinct accepted principals plus a deterministic owner/attacker
  differential; configured or attempted credentials alone do not satisfy the proof gate.
- Supports explicit or discovered OpenAPI inputs plus JavaScript, browser, route, and
  response-guided discovery for modern APIs; authenticated discovery breadth remains an active
  quality priority.

### Parallel scans and Full Coverage

- One logical scan can use parent → plan → shard → merge orchestration across the local worker fleet.
- Full Coverage discovers once, distributes endpoint work, and presents one merged scan and report.
- Dynamic pull-based allocation is the default, with static allocation retained as a rollback path.
- Worker build fingerprints prevent stale or mixed fleets from being treated as valid benchmark or
  release evidence.

### Continuous ASM

- Persistent endpoint inventory and attempt-ledger coverage track what was actually tested by route,
  method, parameter shape, and authentication state.
- Target-scoped improve, recon, and focused SQLi/XSS/auth/BOLA actions choose bounded next work from
  current coverage gaps.
- Scheduler decisions, target campaign activity, hypotheses, recommendations, and proof-family gaps
  are visible without cluttering the normal scans list.

### Deep Hunt

- Deep Hunt is the canonical keyless AI investigation workflow through `/agent/hunt/*`.
- The current Codex, Claude Code, or OpenCode session supplies the planner; no separate stored LLM
  provider key is required.
- Standard installs enable confirmation-gated execution by default. Target authorization, an
  expiring target-bound approval, same-origin enforcement, and hard turn/request/action ceilings
  remain mandatory. Set `AI_OPS_ROUTER_EXECUTE_ENABLED=false` for a global kill switch.
- The free-form loop can use bounded active scanner templates but cannot issue arbitrary
  state-changing HTTP. Tool-backed claims enter as Suspected; supported claims reach Verified only
  through deterministic server proof and controlled restoration-aware workflows.

### Evidence and operator workflows

- Expanded Findings, Evidence, Exposure, Timeline, Mission Ledger, Exceptions, retest, and
  application-graph workflows.
- Content-free evidence manifests and bundles preserve provenance while avoiding raw evidence in
  routine exports.
- The web UI includes an in-app Docs page that renders the installed README for setup, workflow,
  safety, and troubleshooting guidance.

### AI security previews

- AI Gate tests chat, RAG, agent, widget, MCP, and tool boundaries with production-safety controls,
  transcript redaction, replay, and longitudinal campaign history.
- Model Intake checks artifact provenance, checksums, detached signatures, unsafe serialization,
  license/governance metadata, trust anchors, and deployment policy readiness without executing
  model code.
- AI Gate and Model Intake remain **preview** surfaces in 0.7.0 because their complete release-level
  real-stack E2E matrices are not yet implemented.

### Installation, upgrades, and release engineering

- Supported first-run installer and agent launch flows for Codex, Claude Code, and OpenCode.
- Fail-closed database migrations, backup/restore tooling, and a documented upgrade and rollback
  path from the previous published release.
- Locked Python dependencies, immutable scanner assets/templates, pinned base images, Next.js
  16.2.10, and Node.js 24 LTS.
- Native `linux/amd64` and `linux/arm64` image builds, exact-candidate validation, Apache-2.0 OCI
  labels, version-specific notes, and multi-architecture Docker manifests.

## Install

```bash
curl -fsSL https://install.shakerscan.com | sh
```

Then open [http://localhost:3000](http://localhost:3000), or start an agent inside the installed
runtime:

```bash
shakerscan agent codex
# or: shakerscan agent claude
# or: shakerscan agent opencode
```

## Upgrade from 0.5.7

Back up before upgrading:

```bash
shakerscan backup
curl -fsSL https://install.shakerscan.com | SHAKERSCAN_START=0 sh
shakerscan start
shakerscan status
```

After startup, verify the API, UI, worker build status, existing targets/findings, and one safe Quick
scan. Follow the complete [upgrade and rollback runbook](../upgrade-and-rollback.md). Required schema
invariants fail closed instead of allowing services to continue on a partially migrated database.

## Supported deployment boundary

ShakerScan 0.7.0 is a trusted-operator, self-hosted release. It does not provide ShakerScan login,
users, roles, tenant isolation, or comprehensive historical evidence-secret rewriting. Localhost is
the default. Keep remote deployments behind Tailscale, a VPN, firewall, or an authenticated reverse
proxy, and treat scan results, evidence, configuration, and backups as sensitive.

Multi-Node coordination across several VPS hosts is not included in 0.7.0. It is the primary
post-0.7 functional initiative; the current release provides the local parallel-scan substrate on
which that fleet model will build.

## Release validation

The release workflow publishes only from an exact commit reachable from `main` whose `VERSION` is
`0.7.0` and whose generated documentation, locked scanner build, unit/contract suite, release gates,
production dependency audit, and UI build pass. Release-candidate E2E, benchmark, installer, and
post-publish evidence are tracked separately in the
[release-readiness checklist](../release-readiness.md).
