# ShakerScan 2.5.4

This release advances the AI-driven Hunt: methodology-first investigation with shared target
knowledge, deterministic authorization proof persisted into findings, cross-principal verification
for selected header/bearer credentials, and a browser-backed XSS verifier fix found during an EC2
end-to-end exercise. It also unifies the public posture check so `shakerscan check` returns the same
result whether it talks to the hosted service or a connected instance.

## Hunt investigation and methodologies

- Methodology-first investigation: a Hunt starts with no methodology, requests concise metadata-only
  suggestions from shared target knowledge, reads exactly one relevant methodology, and binds it only
  when used. Suggestions never grant or resize scope, capabilities, policy, approval, or budget.
  (#216, #217)
- Shared service evidence and prior-knowledge reuse let Scan, Hunt, and imported context enrich one
  target understanding instead of rediscovering it per workflow. (#216, #217)
- Hunt service execution, pinned NSE coverage, and measured replay settlement were stabilized; actual
  request and reservation use is reconciled in the worker record, and one failed candidate no longer
  fails a whole batch action. (#214)
- Budget continuation lets an operator explicitly extend an unfinished Hunt through a bounded
  amendment; limits are never increased automatically. (#217)

## Authorization proof and credentials

- Deterministic cross-principal authorization proof is completed into persisted findings, so a
  verified access-control differential is retained with its evidence rather than left transient.
  (#221)
- `authz.verify` accepts an exact primary/secondary managed-principal pair as an alternative to
  interactive session references, so Hunts using selected bearer or authorization-header credentials
  can run cross-principal proof. Admission validates both selected profiles and their scope before
  reservation; the worker revalidates target approval and profile versions before decrypting headers.
  The existing session route and deterministic proof contract are unchanged. (#223)
- Hunt capability manifests advertise the full request envelope and concrete call URLs, skill
  suggestions return a concrete Hunt-scoped read URL, and auto-bound prerequisites can be read and
  then reported as used. Hunt responses link both findings and investigation-candidate review
  surfaces. (#223)

## XSS verifier

- The Hunt `xss.verify` browser path no longer fails with a generic signal exit on browser-backed
  targets. The typed proxy-connection-limit reason is preserved when a scanner is killed, and an
  explicit deep DOM check of one query parameter is routed to the pinned Playwright proof runtime
  while ordinary query checks stay on Dalfox. Verified browser XSS on an authorized alternate port is
  persisted with a fingerprint distinct from the target's default service. This change does not alter
  container privileges or memory limits. (#224)

## Public check

- `shakerscan check` returns the same factual observations, in the same schema and format, whether it
  reaches the hosted `pub.shakerscan.com` service or a connected OSS/Enterprise instance. A shared
  posture engine backs both, served on an instance through a new `POST /public/check` route that runs
  one bundled engine process with a minimal environment (no database or API credentials), a timeout,
  and a concurrency cap. Instance checks apply the instance's own policy and are not sent to the
  public service. (#222)

## Validation and limits

Main was green on the candidate commit across the Python suite, CodeQL, build-candidate, authenticated
assurance, browser login QA, Hunt record integrity, and repository hygiene. The build was exercised on
EC2 against disposable Juice Shop with two authorized principals: a credentialed two-principal Hunt
reproducibly produced evidence-backed SQL injection and cross-principal (BOLA) access-control findings
through the deterministic verifiers, and the deterministic Scan produced its expected header-hygiene
baseline. The `shakerscan check` public/instance parity and the `xss.verify` browser-target fix were
confirmed live. Findings created by a Hunt remain evidence-backed candidates; only deterministic proof
contracts mark a finding verified. The release candidate still requires exact-image certification,
published-version smoke, and stable-channel promotion before this version is public.
