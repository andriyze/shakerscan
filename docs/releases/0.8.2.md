# ShakerScan 0.8.2

ShakerScan 0.8.2 is a Fleet image-selection patch found during physical clean-install acceptance of
0.8.1 on two Linux VPS hosts. It preserves the 0.8.1 product and trust boundaries.

## Fix

- Fleet preflight and initialization now honor the release image tag selected by the installed
  `shakerscan` launcher. A curl-installed release therefore resolves and persists its own scanner
  image by immutable digest instead of silently falling back to the mutable `latest` tag.
- Explicit `SCANNER_IMAGE_REPO`, `SCANNER_IMAGE_TAG`, `FLEET_WORKER_IMAGE_DIGEST`, and
  `--worker-image` selections remain supported; the command-line `--worker-image` remains the most
  specific choice.

## Install

```bash
curl -fsSL https://install.shakerscan.com | sh
```

The generated launcher pins ordinary start, restart, Fleet, and agent operations to `0.8.2` unless
the operator explicitly selects another image tag.

## Docker images

- `shakerscan/shakerscan-scanner:0.8.2`
- `shakerscan/shakerscan-api:0.8.2`
- `shakerscan/shakerscan-ui:0.8.2`
- `shakerscan/shakerscan-model-intake-signer:0.8.2`
- Platforms: `linux/amd64`, `linux/arm64`

## Supported deployment boundary

ShakerScan 0.8.2 remains a trusted-operator, self-hosted release. Localhost is the default; remote
operator access belongs behind Tailscale, a VPN, firewall, or authenticated reverse proxy. Fleet
production support remains limited to the outbound-only HTTPS broker. Fleet WireGuard and AI Gate
remain preview surfaces, and the Model Intake Firecracker tier remains an explicit AMD64 Linux/KVM
host installation.

## Release validation

The release workflow validates the exact `v0.8.2` commit reachable from `main`, builds and tests the
locked scanner, API, UI, and signer images, audits production dependencies, verifies clean and
stateful upgrades, and publishes multi-architecture manifests. Post-publication acceptance repeats
the unmodified public curl command on two clean Linux VPS hosts and verifies broker Fleet enrollment
uses the 0.8.2 scanner digest.
