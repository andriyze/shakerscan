# ShakerScan 2.8.0

**Status:** candidate prepared 2026-10-08. Publication and stable-channel promotion are pending.

This release brings the changes merged since 2.7.1 (#335–#359): Hunt permission requests that a
person approves from the terminal, one attached credential list per Hunt target, a coverage ledger
and checkpoint for Hunt planners, verified DAST exposure checks, concurrent SQLi verification within
the pacing contract, honest budget and coverage reporting, and one address classifier shared by the
device, network, SSH, Hunt direct-origin and SMTP destination paths. Most fixes come from the
2026-10-07/08 soak retests behind an Enterprise gateway and from external and adversarial reviews.
It ships client 0.8.0 in source.

## Upgrade notes

- **Policy change: shared address space is private.** 100.64.0.0/10 (carrier-grade NAT and
  Tailscale node addresses) is now private-network space for registered targets and connected
  devices, in every embedded IPv6 spelling. A deployment that refuses private-network targets
  refuses it unless the target is in a Lab environment. To scan Tailscale targets, set
  `SHAKERSCAN_PRIVATE_NETWORK_TARGETS=allow`. A Hunt never authorizes such a destination. (#358)
- **New optional setting `SHAKERSCAN_NAT64_PREFIXES`.** Comma-separated network-specific RFC 6052
  prefixes (/32–/96), empty by default, passed to the API and workers by every Compose file.
  `/health` reports it under `deployment_policy.nat64_prefixes`. (#358, #359)
- **A malformed `SHAKERSCAN_NAT64_PREFIXES` refuses to start.** After the upgrade the API, scan,
  broker and Gungnir workers stop with an error naming the setting. Fix or clear the value before
  upgrading. (#359)
- **`include_families` is additive.** Families named in `include_families` join the selected
  preset rather than replace it. Send `"preset": "custom"` for exactly the named families. Preview
  and `POST /scans` now return `include_families_mode` (`exact` or `added_to_preset`),
  `requested_families`, `resolved_families` and `families_added_by_preset`. (#352)
- **Subdomain discovery scope fix.** In 2.7.1, an in-scan "Discover subdomains" admitted every
  discovered name under the root domain as an endpoint, so passive templates tested sibling hosts
  and their findings were filed under the scanned target (one soak scan filed 58 findings from 7
  subdomains). Discovered names are now listed in the report and recorded as targets, and are never
  tested by the scan that found them; scan them as their own, separately authorized targets.
  Findings filed this way by earlier scans are not rewritten. (#337, #341)
- **SMTP policy on fleet and broker workers.** A worker-launched process reads an empty or missing
  `SHAKERSCAN_PRIVATE_NETWORK_TARGETS` as `refuse` for SMTP MX destinations, and the SMTP policy is
  the stricter of the local and admitted settings. `docker-compose.worker.yml` and
  `docker-compose.broker-worker.yml` now pass that setting and `SHAKERSCAN_NAT64_PREFIXES`.
  Canonical worker Scans do not run the SMTP check today. (#359)
- **`sensitive_exposure` is now a passive, default family** in both the `passive` and
  `standard_active` presets, with no Lab gate. Content discovery requests 17 more curated paths
  (125 instead of 108); a preset-selected exposure batch is best-effort. (#346)
- **Exposure fingerprints are installation-keyed.** Fingerprints recorded before this release
  (`scrypt:`) do not match new ones (`scrypt-keyed:`), and a broker worker keys them with its own
  node-local key, so they match per node, not across a fleet. (#349)
- Coverage score policy is v9; stored v8 reports keep their numbers. The crawl ceiling scales to
  Balanced 2,000 requests / 360 s and Thorough 3,000 / 600 s. (#341)

## Hunt

- **Permission requests, terminal-first (E2, E3).** A refusal a person could allow is recorded with
  a closed reason code (published in `GET /hunts/contract`); the refused action is parked under its
  idempotency key and a permission request is raised. Only that action waits
  (`awaiting_permission`). Grants reuse existing mechanisms (budget amendment, capability flag,
  destination overlay, credential use); a granted request re-runs full admission under the same
  key. Hard limits, including private, loopback, link-local, metadata and reserved destinations,
  never become requests. Requests expire after 24 h or at the Hunt deadline. (#353)
- **Approve in the client.** `shakerscan approve <id> | --all-pending`, `shakerscan deny`,
  `shakerscan hunt permissions list|show|wait` and `--allow` on `hunt start` and `agent`. With an
  Enterprise token the person proves themselves with TOTP or a security key through the gateway's
  step-up routes; on local OSS it is a y/N on the engine route, and the host is the trust boundary.
  Nothing that decides runs without an interactive terminal. MCP returns
  `outcome: awaiting_permission`, and `shakerscan_hunt_permission_wait` waits; no MCP tool can
  decide. The gateway contract (G1) is defined in `docs/hunt-permission-requests.md`. (#353, #354)
- **Live grants run.** An approved `target.authorize` now runs: dispatch checks the destination on
  its live grant (pinned public addresses, unrevoked row, scheme, host and port), and a refusal at
  dispatch releases the hold at once as `dispatch_authority_rejected`. After a denial the same
  subject is not asked again for 15 minutes, keyed on a stable identity (IDNA ASCII host, port,
  profile) so DNS rotation or host spellings cannot bypass it. (#356, #357, #358)
- **Credentials (E1).** A Hunt may use every credential attached to its target: its own and those
  shared to it by grant. Every choice is checked before decryption, an unattached credential is
  never decrypted, and each use is recorded in `hunt_credential_uses` (ids only, with its source,
  including `selected_shared_from:<target>`), exposed read-only as `credential_uses`. (#350, #351)
- **Integrity.** The first Hunt to verify a finding keeps ownership; later verifiers are recorded as
  `additional` in `finding_hunt_verifications` and both list the finding. A concurrent verifier
  waits up to 90 s and honours cancellation. Finished Hunts are immutable (candidate writes,
  `finish` and `cancel` answer 409). A refreshed finding keeps its own title, naming the proven
  object. (#341, #344, #351, #356, #357)
- **Verification.** `candidate.verify` runs under the Hunt's own authority on Enterprise, where
  autonomous Hunt is off. A verification refused before any request is charged nothing and counted
  as refused; a verification is charged its elapsed wall time. A verified finding is attributed to
  its Hunt. (#340, #341, #351, #354)
- **Coverage ledger and checkpoint.** `POST|GET /hunts/{id}/coverage-angles` and
  `GET /hunts/{id}/checkpoint` let a planner resume from exact coverage angles. Settled claims must
  cite related actions that sent traffic; events are bounded (32 KiB each, 8 MiB per Hunt) and
  redacted. (#336, #339, #351)
- **Agent authorization discovery.** `POST /hunts/{id}/boundary-discovery` derives cross-principal
  read-test drafts from captured traffic, with provenance; preparing one stores an unverified
  candidate. Verification enforces the source binding. Operators still run AI Boundary
  verification. (#335, #339)
- **MCP and CLI.** Definite 4xx refusals reach the agent with their detail; a 4xx after dispatch is
  `outcome: unknown`. Long capabilities wait for the server's wall time. Hunt responses are compact
  by default, with paged full views. The MCP Hunt start takes an `Idempotency-Key`, and the start
  answer carries `budget_warnings`. (#337, #341, #344, #354, #356)

## DAST

- **Verified exposure checks.** `.env` variants, `.git/config` and `HEAD`, Spring actuator `env`
  and `configprops`, OpenAPI/Swagger documents with credentials, `config.json`,
  `appsettings.json`, `web.config`, SQL dumps, backup archives, `.DS_Store`, phpinfo, the Werkzeug
  console, `/debug/pprof/` and the credential stores `.git-credentials`, `.netrc`, `.npmrc` and
  `.pypirc` are each proved by their own grammar under a registered proof contract. Lookalikes,
  placeholders and soft-404 pages stay unverified, and `/actuator/heapdump` is never requested.
  Probes use the scan's selected origin, realistic timeouts and one retry; a probe that still times
  out is named as a gap. (#346, #352)
- **SQLi verification.** Candidates are verified one technique at a time with checkpoints,
  cheapest first, and a stage that cannot finish in the wall left is not started. A slice's
  candidates run concurrently at no higher aggregate rate than its pacing allowed, and the slice is
  charged its elapsed tool wall. Extensions reach every wall-killed or unfunded candidate and are
  never funded below a useful floor. (#341, #344, #345, #347, #352)
- **Honest budgets.** Discovery is charged the tightest proven bound; TLS tool counts are labelled
  `estimated`. Passive template batches reuse unspent wall, retry cut-off packs and name slow
  endpoints; a retry keeps the union of both attempts' matches. (#341, #344, #347)
- **Honest coverage.** An empty family selection is refused with a 422. A selected family with no
  work gets a row (`no_candidates` or `not_planned`). An exposure-only plan is reported
  partial and, with no application finding, `not_examined` with its grade withheld. A superseded slice's timeout no longer lingers in the coverage
  reasons. (#341, #344, #348, #352)
- **Scan input and records.** Known endpoints use one grammar (`POST /api/login username,password`,
  `json:`, `form:`) and unreadable lines are refused. `GET /scans/{id}` redacts secrets in known
  endpoints. Evidence integrity no longer reports `mismatch` for intact JSONB objects. Missing-header
  findings carry the baseline response; analyst verdicts can be cleared. (#337, #341, #347)
- **Form login seeds.** A field list after the path stays a JSON body on POST, PUT and PATCH (a
  query on GET); an HTML form is declared with `form:`, which now also takes the field list
  (`POST /login form:username,password` or `form:username=,password=` is stored as
  `form:username=&password=` and sent `application/x-www-form-urlencoded`). Before, the first was
  refused and the second became one field named `username`. The New Scan help says which encoding
  each spelling sends. A seed shown by `GET /scans/{id}` keeps an empty value empty instead of
  `***`; masking there is display-only and never changes what a candidate sends.

## Security fixes

- **Secret withholding in exposure evidence.** Evidence stores the class, key names and keyed
  fingerprints, never a value; excerpts of configuration documents and secret-bearing bodies are
  withheld. Secret keys match on whole name segments, and URL, host or path values are not treated
  as secrets. Parsing is linear, bounded and off the event loop, so a hostile body cannot stall a
  worker. (#349)
- **Masked archive and HAR.** Every masked view (archive JSON, masked HAR, in-app browser, Hunt
  records) withholds values under secret-named keys at any depth, beside secret-named descriptors,
  in HTML fields and `key = value` text, plus provider-format secrets and PEM blocks. (#352)
  They also withhold secrets a document only *describes*: a labelled value of up to three words
  (`Master key: …`, `API Key: …`) inside any JSON string or YAML/text line, so a value in an
  operation `description` is no longer exported (the last raw `/swagger.json` value after #352),
  and every credential-shaped value inside an OpenAPI security scheme, parameter, header or `x-`
  extension, descriptive fields included. A regression corpus covers each OpenAPI 2/3 secret
  placement, and the masking stays linear.
- **Address classifier.** NAT64 (including declared prefixes), SIIT, IPv4-mapped, 6to4 and Teredo
  spellings are decoded, and the private, metadata and cloud-service blocks apply to every embedded
  IPv4. A zone id no longer hides a cloud-service address. (#357, #358)
- **Device, network and SSH destinations** share the web scope guard's decoder, and the API-side
  Device Hunt and control-authorization replay requests are pinned and checked. (#358, #359)
- **Hunt direct-origin addresses** are judged by the shared classifier at start and again before
  any socket is opened. Non-ASCII Hunt hosts use IDNA 2008/UTS #46. (#358, #359)
- **SMTP MX egress.** The SMTP check (`--smtp-security`) used to contact MX hosts by name without
  classifying them. It now resolves each host once, classifies every address under the scan's
  policy, pins all probes to an admitted address (keeping the MX name as SNI), and records refused
  hosts in `skipped_hosts`. A null MX is reported as such, and no host tested grades N/A. (#359)
- **Cloud-service list.** One list adds the EKS Pod Identity agent (169.254.170.23,
  `fd00:ec2::23`) and Oracle Cloud Classic metadata (192.0.0.192); 168.63.129.16 is refused as a
  Hunt destination. The device deny list derives from it, and the device plane refuses
  255.255.255.255. (#357, #359)

## Client 0.8.0

The client in this tree is 0.8.0: terminal approval commands and `--allow`, a built client names
its source commit (`version`, `doctor`, MCP `serverInfo`), `connect` checks a token before saving
and refuses `http://`, redirects name the https origin, `agent --no-launch` and `agent --allow`
check for the agent binary, and the CLI prints `field: message` for a 422. (#337, #354, #356)

## CI

Required PR checks run as four parallel shards for both `smoke` and `python-suite`, with merged
completeness gates and no check removed; PR browser jobs no longer depend on the Ubuntu mirror;
background CI steps keep their exit status. (#342, #343, #347)

## Known limitations

- Several stdlib-only checks still do not decode NAT64: the Model Intake download guard,
  `target_context`, `doh_permitted` and the RDAP destination. `asset_cohorts`,
  `capabilities/dns` and `capabilities/infrastructure` still use `is_global` directly. (#357, #359)
- API-side device admission still leaves metadata destinations to the worker's check. (#359)
- The SMTP check's MX lookup is a resolver query and is unchanged. (#359)
- The engine's active-scan cap is published but not enforced; the effective cap is the worker
  replica count. (#345)
- Exact request counts for TLS tools are bounded, not counted. `GET /targets` still leaves out host
  assets. (#341)
- Four Balanced SQLi body candidates on a slow target cannot all reach a verdict within the
  Balanced ceiling; Thorough can. XSS verification stays sequential. (#345)
- A nuclei `git-config` suspected finding still appears beside the verified one, and exposure
  findings have no retest route yet. (#346)
- The private HTTP archive still records plaintext body digests for deduplication. (#349)
- BOLA proofs from a shared credential still need owned object references. `ssh.exec` and
  `ssh.host_trust` refusals have codes but raise no request yet, and DNS-out-of-scope and
  discovered-host refusals are not wired to `target.authorize`. (#350, #353)
- Enterprise terminal approval needs the gateway's G1 step-up routes; a gateway without them gets
  an exact error and nothing is decided. (#354)
