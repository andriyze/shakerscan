# ShakerScan 0.8.1

ShakerScan 0.8.1 is a patch release for the public installer and clean prebuilt deployments. It
keeps the 0.8.0 product and trust boundary unchanged while repairing issues found during physical
clean-install acceptance on two Linux VPS hosts.

## Fixes

- The public curl installer and generated `shakerscan` launcher now default to the immutable image
  tag in the downloaded `VERSION` file. A clean 0.8.1 installation therefore pulls all four
  `0.8.1` images instead of depending on incomplete or moving `latest` tags. Operators can still
  explicitly select another tag with `SCANNER_IMAGE_TAG` or `--image-tag`.
- The installed runtime now includes `db/configure-model-intake-signer-role.sh`. Clean installs
  configure the restricted PostgreSQL signer role before starting the Model Intake signer, and an
  upgrade repairs the empty directory Docker created for affected 0.8.0 installs.
- Build-fingerprint discovery no longer mistakes the installer's small host-side `api/` support
  directory for a complete source checkout. Matching API and worker images report a current,
  uniform fleet instead of a false stale-worker condition.

## Install

```bash
curl -fsSL https://install.shakerscan.com | sh
```

The installed launcher pins normal start, restart, Fleet, and agent operations to `0.8.1` unless
the operator explicitly requests another image tag.

## Upgrade from 0.8.0

Back up the installation, refresh the host runtime, and restart:

```bash
shakerscan backup
curl -fsSL https://install.shakerscan.com | SHAKERSCAN_START=0 sh
shakerscan restart
shakerscan status
```

The upgrade preserves PostgreSQL, Redis, results, configuration, targets, findings, and Fleet
credentials. It repairs the omitted signer-role bootstrap file before Compose is evaluated.

## Supported deployment boundary

ShakerScan 0.8.1 remains a trusted-operator, self-hosted release. Localhost is the default; remote
operator access belongs behind Tailscale, a VPN, firewall, or authenticated reverse proxy. Fleet
production support remains limited to the outbound-only HTTPS broker. Fleet WireGuard and AI Gate
remain preview surfaces, and the Model Intake Firecracker tier remains an explicit AMD64 Linux/KVM
host installation.

## Release validation

The release workflow validates the exact `v0.8.1` commit reachable from `main`, builds and tests the
locked scanner, API, UI, and signer images, audits production dependencies, verifies clean and
stateful upgrades, and publishes multi-architecture manifests. Post-publication acceptance repeats
the unmodified public curl command on two clean Linux VPS hosts before broker Fleet enrollment.
