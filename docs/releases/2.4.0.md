# ShakerScan 2.4.0

A clean-install release. 2.3.9 was installed from the public installer on fresh Ubuntu 24.04 hosts
and driven through the CLI, the API and the browser; every finding from that exercise, and the
findings of the follow-up audit of that work, ship here. New: the engine-less client can control an
OSS engine over a trusted LAN. The deployment decision now carries the target's carried-over
finding summary, computed once on the server. Upgrade in place from 2.3.9; 0.8.18 remains the
oldest directly certified upgrade base. No change to the deterministic proof boundary.

## Changes

### Standalone server (#176)

- DNS posture: the DNS-over-HTTPS fallback also covers `NoNameservers`, the class systemd-resolved
  produces for DS/DNSKEY lookups it answers with SERVFAIL. Every Linux install reported DNS
  posture `partial` on every scan; Baseline DNS now succeeds there.
- A target whose certificate the client will not trust no longer fails the whole HTTP baseline as an
  unclassified adapter error. The bound request keeps the TLS cause on the exception chain and the
  action reads `tls_certificate_untrusted`.
- Launcher hints name the installed `shakerscan` command when the installed wrapper execs this
  runtime, and `./scanner.sh` from a source checkout.
- Live scan activity keeps the `[Discovery]` and `[Shard N]` child label on parallel scans.
- A scan that lost its worker lease to an infrastructure restart is offered a plain retry with
  queue-health wording, not a target review.
- Worker Pools: an opt-in pool with no worker reads "not started" and shows the server's remedy,
  which names the installed command. The `/workers` pool summaries carry a `remedy` field.
- Targets page label width, dashboard change-feed wording, New Scan preview reset, and sidebar
  links that no longer prefetch every route on each navigation.

### Scan report and findings (#176)

- `GET /scans/{id}/deployment-decision` carries `carried_over`: the target's unresolved findings
  the scan did not observe, with count, material count, highest severity, and whether the target's
  complete active set was loaded. It is computed next to the gate over the same rows. The scan page
  renders it and keeps its client computation only as a fallback for an older API.
- A row counts as observed by a run only through persisted linkage or a fingerprint the run
  reported. Display strings are no longer used as finding identity, so two findings with different
  fingerprints and the same title, URL and tool stay distinct, and URL paths keep their case.
- The scan page pages through every active target finding; past its cap the card reports a lower
  bound and an incomplete history instead of an all-clear.
- Scan-scoped finding drill-downs carry `freshness=all`, and a `scan_id` view of the Findings page
  defaults to all rows. An explicit freshness choice still wins.
- Hint ingestion (robots.txt, llms.txt) keeps a declared query's parameter names, order and
  multiplicity and drops every value, so route observations are value-free by construction.

### Fleet (#176)

- `fleet init` refuses while scans are queued or running unless `--allow-running-work` accepts the
  interruption. It also refuses when it cannot establish the answer: an unreachable API, a failed
  second request, or a list without a total. A stopped installation is recognised by the absence
  of the api container. The census includes shards, internal, Model Intake and device rows. New
  submissions are not paused during the conversion.
- Preflight says inbound TCP 80 and 443 must be open at the cloud firewall, prints an explicit
  "Inbound firewall" line, and a managed-gateway timeout is explained from the gateway's ACME log.
- Rollback removes fleet directories generated by that attempt and says the pre-conversion backup
  is kept. Output is line-buffered so the preflight table precedes the launcher banner.
- The launcher rounds host RAM and Docker's MemTotal the same way, so the auto worker count no
  longer drifts between the installer shell and the next restart.

### Model Intake (#176)

- Quarantine is granted to the scanner account's group, not the image's hardcoded gid; Compose
  passes the sandbox identity to both workers. A non-root Linux install could not read its own
  quarantine.
- The runner installer uses the release Compose file on an installed runtime, its `status` reports
  what the running API says about the runner, and the provision script no longer tells a
  CLI-managed install to enable the unit by hand.
- The automatic review names the runner receipt verdict and the failing phase; job refresh carries
  `receipt_status`; a calibration run says no known-answer digest is configured; the runner service
  logs job start, finish and verdict to the journal.
- Scanners run BLAS single-threaded, so the image self-test and modelscan survive many-core hosts.

### Trusted-LAN control from the engine-less client (#177)

- `shakerscan start --lan` and `restart --lan` bind the API and UI to an assigned private IPv4
  address, selecting the default-route interface or the one named with `--bind-host`, and fail
  closed on wildcard, public, loopback or ambiguous addresses. Datastore binding is unchanged.
- The laptop client (`pipx install shakerscan`) reaches that engine with `--url` on `doctor`, `api`,
  `hunt` and `mcp`, or through `SHAKERSCAN_API_URL`. See `docs/lan-access.md`.
