# ShakerScan 0.8.3

ShakerScan 0.8.3 is a correctness and release-hardening update for Fleet, Model Intake, browser
scanning, build provenance, and clean installation. It preserves the 0.8.2 product and trust
boundaries.

## Highlights

- Model Intake reports now preserve blocking scanner results, distinguish incomplete runtime
  qualification from a clean result, disclose actual scanner scope and file inventory, and render
  a severity-colored CVE inventory backed by Trivy, OSV-Scanner, and pip-audit evidence.
- Model Intake runtime evidence now validates every required phase, signed subject and containment
  binding, pre-build guest inputs, resource envelope, network telemetry, and conversion lineage.
- Browser discovery retains useful read-only navigation while blocking form submissions,
  state-changing controls, delayed page mutations, and unsafe semantic variants.
- Fleet broker routing, admission, result ingestion, capacity, image drift, lifecycle recovery, and
  worker inventory now fail closed on ambiguity. Database-less broker workers upload checkpoints
  through their lease-scoped HTTPS control-plane channel without attempting local database writes.
- Source builds use one explicit worker-image identity, ship every scanner payload that contributes
  to the build fingerprint, and recreate the Model Intake sandbox from the rebuilt image.
- Release artifacts record both candidate-source and workflow-definition provenance. The hosted
  installer resolves the stable channel first and downloads runtime files from that immutable tag.

## Install

After the stable channel is promoted:

```bash
curl -fsSL https://install.shakerscan.com | sh
```

The generated launcher pins ordinary start, restart, Fleet, and agent operations to `0.8.3`
unless the operator explicitly selects another image tag.

## Supported deployment boundary

ShakerScan 0.8.3 remains a trusted-operator, self-hosted release. Localhost is the default; remote
operator access belongs behind Tailscale, a VPN, firewall, or authenticated reverse proxy. Fleet
production support remains limited to the outbound-only HTTPS broker. Fleet WireGuard and AI Gate
remain preview surfaces, and the Model Intake Firecracker tier remains an explicit AMD64 Linux/KVM
host installation.

## Release validation

The candidate passed 3,094 backend tests, 89 UI tests, all named release gates, the production UI
build, locked Python and production npm audits, scanner and adapter image self-tests, the fixed
Firecracker guest conversion self-test, generated-inventory and installer checks, and clean plus
duplicate-dirty schema upgrades. The real CodeSage report was cross-checked in JSON and HTML.

Physical broker acceptance used separate Linux control-plane and worker VPS hosts. It verified
HTTPS health and authentication boundaries, private PostgreSQL/Redis/object-store ports, joined-node
health and image/state truth, centralized remote scan attribution, durable lifecycle events, and a
reversible drain/resume cycle that restored the original worker capacity.
