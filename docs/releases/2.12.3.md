# ShakerScan 2.12.3

**Status:** never published. Its changes ship in 2.13.0 ([`2.13.0.md`](2.13.0.md)). This note is
kept as the record of the prepared patch.

A patch release of fixes from a read-through of the engine: four names used without an import on
live paths, Hunt action accounting that lost partial results, two writes a refusal rolled back,
input a target controls that failed a whole action, and three web UI corrections. No schema
changes; a rollback restores the pre-upgrade database dump, as for every release
(`docs/upgrade-and-rollback.md`).

## Fixes

- **Deleting a finding with an approved preview works.** `DELETE /findings/{id}` with the approval
  of its preview raised `NameError` (a helper was never imported into the findings routes), so the
  request answered 500 and the finding stayed.
- **Adaptive discovery refinement runs without a URL budget.** With no discovery URL budget set,
  the refinement step read an unbound name and was skipped whole. It now takes the budget from the
  discovery configuration (1,000 URLs when none is set).
- **`form_login` screenshot capture and the calibration script import what they use.** Each used a
  module it never imported.
- **The worker refuses to start on a failed release identity.** The worker entrypoint ran
  `release_identity.py --verify` and ignored its exit status. It now exits, as the API entrypoint
  already does. **This changes worker start-up:** a worker whose image identity does not match its
  release manifest no longer starts.
- **A finding exception with an unparsable `expires_at` answers 422**, not 500.
- **A timed action settles at most the wall time it reserved.** `recon_active`, `sqli_proof`,
  `nosqli_verify`, the browser adapter and the `xss.request_verify` / `sqli.request_verify`
  request proofs could report one second more than reserved at a deadline stop or after rounding.
  That settled as an over-reservation: the action failed and its partial result, or a completed
  proof, was lost. SQLi and NoSQLi also split the wall time that is left across the remaining
  requests and stop as a kept partial when none is left.
- **NoSQLi verification routes by method.** A captured GET was sent to the JSON-body mutator and
  never tested. The verifier also counts a request before sending it, keeps completed proofs when a
  later field errors, and reports every state-changing request it sent.
- **`knowledge.continue` reports a spent budget.** It compared ceilings and the ledger under
  different keys, so a spent budget was never reported.
- **Two writes are kept when the request is then refused.** An expired SSH plan is recorded as
  expired before the confirmation refuses it, and a decision on a permission request whose Hunt has
  ended leaves the request withdrawn. Both were rolled back by the 409 raised after them.
- **Hostile or malformed input no longer fails a whole action.** One unreadable spec document no
  longer aborts the ingest; a login answer with a non-finite `expires_in` or deep nesting no longer
  crashes session establishment; `tls.inspect` reports a certificate with an unsupported key or a
  malformed SAN as partial; receipt redaction survives a string that is not a URL; an SQLi mutation
  error settles as blocked; one host's error no longer fails every host in the takeover check; a
  non-object line no longer fails the port parse; a nameless header no longer drops the headers
  after it; a failing archive recorder no longer replaces a replay result.
- **Boundary-discovery prepare works on a device Hunt.** It always answered 422.
- **Skill suggestions answer 422, not 500, on a catalogue error.**
- **Switching a credential profile off ends its live sessions**, as deleting it does.
- **The prior-knowledge census no longer counts expired candidates as open.**

## Interface

- **Hunt findings are labelled in the Findings list.** Findings a Hunt recorded
  (`source='deep_hunt'`) had no source label.
- **The device page polls a queued scan as live**, as it does a pending or running one.
- **Blocked and exhausted leads have a badge style.**

## Documentation

- **Instructions that named removed routes, commands and UI areas are corrected** in the docs,
  the skills, the slash commands, `llms.txt` and the client help text (the `update` subcommand it
  listed does not exist). The client package is otherwise unchanged and stays 0.12.0.

## Development

- **A static gate rejects undefined names.** `scripts/check_undefined_names.py` reads every tracked
  Python file with pyflakes (its own hash-locked requirement, not a runtime dependency) and fails
  on a name that cannot resolve. It would have reported the four live errors above.

## Known limits

- The worker's identity check fails when the deployment names a version or revision
  (`SCANNER_EXPECTED_VERSION`, `SCANNER_EXPECTED_REVISION`; the release Compose file sets the
  version) that the image does not carry, or when the image's release manifest is unreadable. A
  worker left on another release's image after a partial upgrade now exits at start instead of
  taking work; finish the upgrade with the documented route.
