# ShakerScan 0.8.5

ShakerScan 0.8.5 is a scanner-coverage truth patch found during clean post-publication acceptance of
0.8.4. It restores ModelScan coverage for TensorFlow/Keras HDF5 artifacts and makes Fleet Nuclei
status distinguish an installed tool from execution blocked by the enforced request budget.

## Fixes

- The scanner image now installs the pinned `modelscan[h5py]` dependency set. Repositories containing
  TensorFlow/Keras `.h5` artifacts no longer become incomplete solely because ModelScan's optional
  HDF5 parser was absent.
- The image build creates and scans a deterministic minimal Keras HDF5 model with ModelScan. A future
  dependency or packaging regression fails the image build instead of reaching users.
- Local version/help probes for known network scanners no longer count as target traffic. Fleet
  workers can therefore prove that Nuclei is installed while request-budget enforcement is active.
- Actual Nuclei target execution remains fail-closed in enforced mode because its internal requests
  are not individually metered. Reports now say that Nuclei was blocked by the enforced request
  budget and record no fabricated template coverage, rather than incorrectly saying it was absent.
- Staged Nuclei execution stops after the first budget-blocked wave, preserving the explicit error
  and avoiding misleading follow-on estimates.

## Install

After the release images are published and the stable channel is promoted:

```bash
curl -fsSL https://install.shakerscan.com | sh
```

The generated launcher pins ordinary start, restart, Fleet, and agent operations to `0.8.5` unless
the operator explicitly selects another image tag.

## Supported deployment boundary

ShakerScan 0.8.5 remains a trusted-operator, self-hosted release. Localhost is the default; remote
operator access belongs behind Tailscale, a VPN, firewall, or authenticated reverse proxy. Fleet
production support remains limited to the outbound-only HTTPS broker. Fleet WireGuard and AI Gate
remain preview surfaces, and the Model Intake Firecracker tier remains an explicit AMD64 Linux/KVM
host installation.

## Validation requirement

The exact release commit must pass the complete backend and UI suites, production builds, generated
inventory, named release gates, locked production dependency audits, installer and upgrade smokes,
and clean published-image acceptance for Model Intake, parallel DAST, and broker Fleet. Publication
and stable-installer promotion remain separate fail-closed steps.
