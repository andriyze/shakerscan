# ShakerScan 0.8.7

ShakerScan 0.8.7 carries forward the unpublished 0.8.6 Fleet parallel-execution fix and hardens the
release schema smoke that correctly stopped that candidate before publication.

## Fixes

- Broker workers share the remaining per-domain request allowance fairly across pending children of
  one parallel scan. The first child can no longer reserve the entire allowance and park every
  sibling until the reservation expires.
- Running siblings remain represented by Redis's atomic reservation counter; only children that have
  not yet leased participate in the next fair-share calculation.
- The global per-domain cap, request metering, exact-node placement, and fail-closed behavior remain
  enforced. A database or sibling-count failure does not bypass the limiter.
- The clean/dirty schema-upgrade release gate now distinguishes PostgreSQL's temporary initialization
  server from its final PID 1 process. It no longer starts `createdb` during the official image's
  intentional server handoff, while retaining the same migration and dirty-data assertions.

## Install

After published-image verification and stable-channel promotion:

```bash
curl -fsSL https://install.shakerscan.com | sh
```

The generated launcher will pin ordinary operations to `0.8.7` unless the operator explicitly
selects another image tag.

## Supported deployment boundary

ShakerScan 0.8.7 remains a trusted-operator, self-hosted release. Localhost is the default; remote
operator access belongs behind Tailscale, a VPN, firewall, or authenticated reverse proxy. Fleet
production support remains limited to the outbound-only HTTPS broker. Fleet WireGuard and AI Gate
remain preview surfaces, and the Model Intake Firecracker tier remains an explicit AMD64 Linux/KVM
host installation.

## Validation requirement

The exact release commit must pass the complete backend and UI suites, production builds, generated
inventory, named release gates, locked production dependency audits, installer and upgrade smokes,
and clean published-image acceptance for Model Intake, parallel DAST, and broker Fleet. Publication
and stable-installer promotion remain separate fail-closed steps.
