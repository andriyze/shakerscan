# ShakerScan 0.8.16

ShakerScan 0.8.16 is a release-truth and product-separation patch over 0.8.15. It was prepared from
literal clean curl installations on a control-plane VPS and an outbound-only broker worker VPS.

## Fixes

- Official scanner/API images now bake their semantic release identity. Broker workers therefore
  stamp DAST reports with the actual release instead of `dev`; a digest rollout discards the old
  container override and adopts the replacement image's identity.
- Local Fleet builds bake their commit identity as well, without weakening the existing local-build
  telemetry badge or digest-pinned production path.
- Model Intake serialization checks inspect the complete immutable repository snapshot. Selecting a
  safetensors deployment artifact no longer causes ModelScan and the built-in pickle scanner to skip
  a co-published `.bin`, `.pt`, or `.pkl` alternate.
- The default `GET /scans` and DAST Scans UI exclude Model Intake evidence scans. The dedicated Model
  Intake workflow opts into those rows when selecting generated evidence, and direct scan/report
  links remain available.
- Smart-scan reports no longer display a false `0%` parameter-coverage claim when the scanner issued
  active parameter probes but discovered no parameter inventory. The UI reports probes and the
  missing denominator explicitly.
- Execution-location copy uses correct singular/plural worker labels. Every wrapper subcommand now
  treats `--help` as non-mutating; `shakerscan agent --help`, `shakerscan mcp --help`, and the legacy
  research adapter provide focused usage instead of launching work or returning silent output.

## Validation

The frozen candidate must pass the complete backend and UI suites, all named release gates,
dependency audits, generated documentation checks, production multi-architecture builds, clean and
dirty upgrade smokes, and exact-manifest verification. Post-publication acceptance must repeat a
literal clean curl installation on both VPSs, broker enrollment, exact-node three-shard DAST,
worker-loss reclaim, centralized persistence, and the public tiny-model Model Intake review.

## Install

After publication and stable-channel promotion:

```bash
curl -fsSL https://install.shakerscan.com | sh
```

The generated launcher pins ordinary operations to `0.8.16` unless the operator explicitly selects
another image tag.

## Supported deployment boundary

ShakerScan 0.8.16 remains a trusted-operator, self-hosted release. Localhost is the default; remote
operator access belongs behind Tailscale, a VPN, firewall, or authenticated reverse proxy. Fleet
production support remains limited to the outbound-only HTTPS broker. Fleet WireGuard and AI Gate
remain preview surfaces, and the Model Intake Firecracker tier remains an explicit AMD64 Linux/KVM
host installation.
