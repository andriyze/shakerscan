# ShakerScan 2.5.1

This release completes connected-device Hunt access to nonstandard ports and adds bounded Nmap
script checks. It also fixes accounting and credentialed browser behavior found during an EC2
end-to-end Hunt exercise. The separate client 0.7.1 release adds a credential-free public MCP
check for users who have not configured a private ShakerScan instance.

## Hunt and connected devices

- Authenticated Hunt actions can reach an operator-selected origin on a nonstandard port. Browser
  navigation and interaction on a device use that service origin under the device binding and
  policy, rather than always assuming port 80. Web and device targets retain their distinct
  authorization and destination checks. (#204, #205)
- Device Hunts can run four allowlisted Nmap NSE checks with server-controlled scripts, ports,
  addresses, timeouts, and output bounds. Discovery authority and budgets are enforced before
  execution. NSE observations are evidence, not verified vulnerabilities without deterministic
  proof. (#205)
- Saved credential and request-collection replay now settles its actual requests and reservation
  use in the worker record. Failed actions keep their semantic outcome, and a single bad replay
  does not silently appear as a successful action. (#205)
- Browser login checks handle script-driven and polling JavaScript login pages, redirects, gzip
  replay, and an authorized HTTPS-to-HTTP service transition. The real Chromium login check is
  private QA; it does not export an authenticated browser session to later actions. (#205)

## Client 0.7.1

- With no instance configured, `shakerscan mcp` exposes only
  `shakerscan_public_check(target)` through the public posture service. A configured instance
  retains its own private tool catalogue; failed private connections never fall back to public.
  The same credential-free service backs `shakerscan check`. (#203)

## Validation and limits

PR #205 passed the Python, Chromium, acceptance, and full-stack smoke checks. The final build
was exercised on EC2 against an owned TV-like service fixture on ports 8008 and 8443, Honey,
and disposable Juice Shop. Hunt E2E produced deterministic DOM XSS proof and a verified Juice
Shop finding. The media fixture is an emulation, not physical TV acceptance. The release
candidate still requires exact-image certification, published-version smoke, and stable-channel
promotion before this version is public.
