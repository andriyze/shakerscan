# ShakerScan 0.8.4

ShakerScan 0.8.4 is a parallel-DAST correctness release. Full Coverage now adds fleet-wide endpoint
breadth without removing the complete Smart-scan capabilities users expect, and it reports partial
execution honestly.

## Highlights

- Full Coverage runs a complete Smart backbone concurrently with self-contained endpoint shards, so
  browser discovery, DOM-XSS, posture, and global checks are preserved instead of fragmented or
  silently skipped.
- Endpoint discovery is a durable, placed job. Broker-only targets are discovered on an eligible
  worker, not accidentally from the control plane, and discovery failure stops the parent rather
  than producing an empty false-success fan-out.
- Fan-out is transactional: the exact child set is committed before queue publication, merge waits
  for that complete set, and restart recovery repairs the database-to-queue seams.
- Endpoint shards carry immutable worklists and require no control-plane database access. They avoid
  repeated crawling, browser work, fuzzing, Nuclei, and unrelated authentication probes while still
  running the assigned active checks.
- Failed, cancelled, or partial children produce `technical_outcome: INCOMPLETE`, an unreliable
  grade marker, a review-required deployment decision, and explicit assigned-versus-attempted
  endpoint accounting.
- Merged reports retain per-shard worker/node identity, timing, errors, skipped-check context,
  request budgets, and scanner execution receipts while centralizing deduplicated findings under
  the logical parent scan.
- Dashboard queue counts now describe user-visible scans. Internal discovery/shard work remains
  available as separate operational counters, and stale Redis job hashes can no longer leave the UI
  showing one scan running forever.
- Scan creation and detail pages explain planned aggregate/backbone request budgets, durable
  discovery, endpoint assignments, attempts, and partial outcomes without presenting estimates as
  hard ceilings or complete coverage.

## Install

After the release images are published and the stable channel is promoted:

```bash
curl -fsSL https://install.shakerscan.com | sh
```

The generated launcher will pin ordinary start, restart, Fleet, and agent operations to `0.8.4`
unless the operator explicitly selects another image tag.

## Docker images

- `shakerscan/shakerscan-scanner:0.8.4`
- `shakerscan/shakerscan-api:0.8.4`
- `shakerscan/shakerscan-ui:0.8.4`
- `shakerscan/shakerscan-model-intake-signer:0.8.4`
- Platforms: `linux/amd64`, `linux/arm64`

## Supported deployment boundary

ShakerScan 0.8.4 remains a trusted-operator, self-hosted release. Localhost is the default; remote
operator access belongs behind Tailscale, a VPN, firewall, or authenticated reverse proxy. Fleet
production support remains limited to the outbound-only HTTPS broker. Fleet WireGuard and AI Gate
remain preview surfaces, and the Model Intake Firecracker tier remains an explicit AMD64 Linux/KVM
host installation.

## Candidate validation

Before the release tag, the exact candidate must pass the complete backend and UI suites, production
build, generated inventory, named release gates, production dependency audits, clean installer and
upgrade checks, current-build physical DAST acceptance, and digest-pinned broker Fleet acceptance.
Publication and stable-installer promotion remain separate fail-closed steps.
