# ShakerScan 0.8.17

ShakerScan 0.8.17 is a corrective release over 0.8.16, prepared after literal clean curl installs
and physical broker-fleet fault injection found a mismatch between the source Dockerfile contract
and the official registry build.

## Fixes

- Official scanner and API builds now pass the semantic release version into their shared image.
  Broker workers therefore stamp DAST and Model Intake evidence with the published version instead
  of `dev`.
- Every native release job pulls its just-pushed scanner/API digests and reads `SCANNER_VERSION`
  back from image configuration. Publication stops if either value differs from `VERSION`.
- Validation images use the same versioned build contract, so frozen-candidate E2E exercises the
  exact identity behavior shipped to users.
- Broker lease heartbeats run on a dedicated native thread. Long Model Intake parsers or scanner
  calls can no longer starve the shared asyncio loop and trigger a false five-minute stale-scan
  termination while the remote worker is healthy.
- The Dashboard and exact-node scan selector use correct singular worker labels. Completed shard
  cards replace duplicate `completed · completed` text with execution-node attribution.
- Fleet operator examples select `docker-compose.release.yml` in curl installations and
  `docker-compose.yml` in source checkouts while retaining the explicit `shakerscan` project name.

## Release boundary

ShakerScan 0.8.17 remains a trusted-operator, self-hosted release. Localhost is the default; remote
operator access belongs behind Tailscale, a VPN, firewall, or authenticated reverse proxy. Fleet
production support remains the outbound-only HTTPS broker. WireGuard and AI Gate remain preview
surfaces. The Model Intake Firecracker tier remains an explicit AMD64 Linux/KVM host installation.

## Required validation

Before promotion, the frozen candidate must pass the full backend/UI suites, all release gates,
dependency audits, CodeQL, native amd64/arm64 publication, manifest and OCI-label verification, and
literal clean curl installation on both control-plane and worker VPSs. Clean acceptance must prove
versioned DAST output, broker enrollment, exact-node parallel execution, worker-loss reclaim,
central result/artifact persistence, datastore isolation, and the public tiny-model Model Intake
path.
