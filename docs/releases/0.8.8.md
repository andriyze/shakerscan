# ShakerScan 0.8.8

> **Unpublished candidate:** validation stopped before registry publication when the hosted runner's
> connection reset while downloading the checksum-pinned Playwright base-image layer. No 0.8.8
> images were published and the stable installer never selected this version. The Fleet fix and
> bounded clean-build retry are carried forward to 0.8.9.

ShakerScan 0.8.8 fixes a Redis Stream route-lifecycle race found during clean published-image Fleet
acceptance of 0.8.7. It carries forward the complete 0.8.7 feature set and does not expand the
supported deployment boundary.

## Fixes

- Broker workers no longer receive an opaque HTTP 500 when the final acknowledgement on an empty
  placement route removes its Redis Stream consumer group while another worker is already polling
  that route.
- Both abandoned-lease reclaim and fresh-work long polling recognize only Redis's specific
  `NOGROUP` lifecycle response, refresh the base queue or any still-registered route, discard a
  route that was already pruned, and return an ordinary no-work response.
- The recovery does not start a second long poll, so broker request duration remains bounded.
  Connectivity, read-only replica, protocol, and every other Redis error continue to fail visibly.
- Managed HTTPS documentation now calls out the persistent Caddy certificate volume. Ordinary
  reinstall and upgrade flows preserve it; deleting it forces new ACME issuance and can trigger a
  public CA's duplicate-certificate limits during repeated destructive lab rebuilds.

## Validation

The release candidate must pass the full backend and UI suites, production builds, generated
inventory, named release gates, dependency audits, installer and upgrade smokes, and published-image
acceptance. The exact prune-while-polling timing is also exercised against real Redis, in addition
to deterministic unit coverage for both lease operations and for propagation of unrelated errors.

## Install

After publication and stable-channel promotion:

```bash
curl -fsSL https://install.shakerscan.com | sh
```

The generated launcher pins ordinary operations to `0.8.8` unless the operator explicitly selects
another image tag.

- Platforms: `linux/amd64`, `linux/arm64`

## Supported deployment boundary

ShakerScan 0.8.8 remains a trusted-operator, self-hosted release. Localhost is the default; remote
operator access belongs behind Tailscale, a VPN, firewall, or authenticated reverse proxy. Fleet
production support remains limited to the outbound-only HTTPS broker. Fleet WireGuard and AI Gate
remain preview surfaces, and the Model Intake Firecracker tier remains an explicit AMD64 Linux/KVM
host installation.
