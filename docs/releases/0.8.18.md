# ShakerScan 0.8.18

ShakerScan 0.8.18 is an installer and first-run hardening release. It closes gaps found by literal
clean-install testing after 0.8.17 and simplifies Model Intake setup for standalone users.

## Fixes

- Startup now fails closed when the UI, API, and workers do not share one build identity. If the
  registry is temporarily unavailable, startup uses the cache only when every exact-version image
  is present, then performs the same identity check before reporting ready.
- The UI reports an immutable identity baked into its image. A runtime environment value cannot
  relabel an old UI as the requested release.
- The release candidate runs an isolated installer-created stack and proves UI/API/worker identity,
  local Model Intake authentication, and Firecracker guidance. Stable promotion validates a
  semantic receipt from the literal public curl installer.
- Standalone loopback installs receive a short-lived Model Intake browser session signed with a
  separate local secret. The durable operator token never enters the UI, and remote or managed
  deployments continue to require a named reviewer credential.
- Firecracker setup is one host command. Curl installations automatically enter
  `~/.shakerscan`; source builds automatically enter the actual checkout before downloading,
  verifying, installing, connecting, and checking the runner.
- Standalone and macOS dashboards show one worker count. Local-versus-remote capacity is shown only
  when Fleet is enabled and supported.

## Security boundary

ShakerScan remains localhost-only by default. The automatic Model Intake browser session is accepted
only for loopback-configured installs, carries no approval roles, expires after eight hours, and is
rejected without a loopback browser origin. Remote deployments keep the existing explicit reviewer
credential boundary. The Firecracker runner remains an opt-in root action on a compatible Linux/KVM
host; the API and UI do not perform privileged host mutation.
