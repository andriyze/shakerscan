# ShakerScan 2.8.2

**Status:** candidate prepared 2026-10-10. Publication and stable-channel promotion are pending.

This is a fixes-only patch release. Hunt no longer shows target secrets it finds to the planner or
in its masked archive, and lets the planner use them by reference (#371). Masked archive exports
are bounded and linear on hostile text (#374) and no longer carry the raw body digest. Hunt
permission bounds use one strict IDNA 2008/UTS #46 host spelling (#373). Scope patterns, POST
/discovery and the CT monitor respect public-suffix boundaries (#378). The running-scan
authorization re-check gains its own deadline and covers more running work. Slow SQLi candidates
get the remaining budget follow-ups, and the client's state and data directories are hardened
(#382).

## Upgrade notes

- **Hunt withholds secrets it finds.** In 2.8.1, credential values in database dumps, `web.config`
  pairs, phpinfo tables and redirect URLs could reach the planner and the masked Hunt archive. They
  are now shown as `[withheld:n]` references; `request_bindings[].withheld_ref` sends the exact value
  back to the target under the existing active-testing authority, budgets and scope. (#371)
- **`artifact.inspect` reserves two requests.** When tab-separated rows in a window cannot be told
  apart from a dump's `COPY` rows, the inspect reads the resource's first 64 KB once per resource
  and remembers the verdict; only then does it spend the second request. (#371)
- **Masked archive exports carry no raw body digest.** JSON and HAR exports in the masked
  (default) view no longer include the raw request or response body SHA-256, which could confirm a
  guess at a masked low-entropy value. Raw exports keep it.
- **Stored Hunt bounds are re-checked.** Pre-authorizations stored by 2.8.1 or earlier were parsed
  with IDNA 2003. A host bound whose spelling changes under IDNA 2008/UTS #46 is withheld and offered
  back once for `shakerscan approve`; one that names a public suffix (`*.co.uk`, `*.github.io`) is
  kept as stored, listed under `refused_bounds`, and covers nothing. (#373, #378)
- **Public-suffix roots.** Targets stored under a public-suffix `root_domain` (`co.uk` for
  `shop.example.co.uk`) are recomputed once at startup. A scope root, wildcard bound, discovery
  domain or monitored root that spans registrants (`amazonaws.com`, `*.kawasaki.jp`) is refused.
  An apex such as `typeform.com` keeps its DNS posture checks. (#378)
- **POST /discovery is admitted.** Discovery runs only for a domain under which a person added a
  target on the Targets page, one run per apex at a time and at most
  `SHAKERSCAN_DISCOVERY_MAX_ACTIVE` (default 2) engine-wide. Targets a scan, discovery, the CT
  monitor or a Hunt agent created do not count; adding such a target on the Targets page makes it
  the person's. A host stored before 2.8.2 that has rows attached under it must be added again
  once. (#378)
- **The CT monitor is capped.** Each apex gains at most `SHAKERSCAN_CT_MONITOR_DAILY_CAP` (default
  100) new targets per UTC day; names over the cap are counted, not added. (#378)

## Hunt

- Withheld values carry a reference, a three-character preview, the length and a keyed
  fingerprint. Every public URL field of an HTTP result (`location`, `final_url`, redirect chain,
  selected `Location`-style headers) is masked, for plain requests as for bound workflows. (#371)
- A withheld value is sealed exactly as decoded, so a password with significant spaces is sent back
  unchanged, and distinct values get distinct references. (#371)
- An action's sealed private result (captures, withheld values, dump column knowledge) stays within
  65,536 bytes. References are kept first; what does not fit is reported in `not_retained`, and its
  reference refuses rather than sending a different value. (#371)
- Permission bounds, destination subjects, credential home hosts and approval screens use one
  strict IDNA 2008/UTS #46 spelling: `straße.example` is `xn--strae-oqa.example`, never
  `strasse.example`. Numeric host text that is not canonical dotted-decimal IPv4 is refused for
  targets, scopes and bounds. (#373)

## Scans and scope

- One bundled, pinned Public Suffix List decides every wildcard, scope root, binding root,
  discovery domain and CT-monitor root. Same-site checks in form login and vendor-risk use it too.
  (#378)
- PATCH `/targets/{id}` cannot edit `metadata_json.declared` or `created_via`.
- SQLi continuation follow-ups: first slices are reserved only where the compile can admit them,
  nothing is reserved in the Scan's last round, and a last chance is sized above the wall its unit
  was already stopped at.

## Running-scan authorization

- **The re-check has its own deadline.** The safety deadline runs from the last successful
  authorization confirmation. A check whose database call never returns no longer keeps an action
  running: it is cancelled and the action is interrupted as `authorization_unverified` within the
  tolerance (about 10 s). The pre-dispatch check and its retries are bounded the same way. A slow but
  answering check keeps the action running.
- **More running work is re-checked.** Device posture and probe scans, AI scans, and actions running
  on a fleet node now stop when the authorization that admitted them is revoked, expires, or no
  longer covers the target. Device and AI runs are re-checked against what their admission checked;
  runs admitted without a receipt are not watched, as for a passive local Scan. A fleet node asks the
  control plane while an action runs; the control plane also refuses heartbeats for a withdrawn
  action (409, `authority_withdrawn:<reason>`) and records its result as a partial authorization
  stop whatever the node reports.

## Archive exports

- Masked exports are built in worker processes with byte budgets, admitted before reading, and
  never on the API event loop; browse pages have their own slots. A busy archive returns 503 with
  `Retry-After`, which the UI honours. The free-text redaction rules run in linear time on hostile
  input, including URL userinfo passwords. (#374)

## Client 0.8.2

- State and data directories resolve `SHAKERSCAN_STATE_DIR`/`SHAKERSCAN_DATA_DIR`, then XDG, then
  beside `SHAKERSCAN_CONFIG_DIR`, then `~/.local`. `/` and unwritable directories give an error
  naming the variable to set. (#382)
- Migrating records from the old location completes interrupted moves, never leaves a partial
  record, and never replaces a record already set aside. (#382)
- `scripts/clean-shakerscan.sh` removes only the client's own workspace records and keeps the agent
  workspace unless `--agent-workspace` is given. (#382)

## Known limitations

- Finding retests are still checked only when they are admitted, not while they run.
- An AI target scan that is stopped for authorization does not keep the findings it had made before
  the stop; the result records the authorization stop.
- A fleet node on an older image does not ask the control plane while an action runs: its tool runs
  until its lease lapses, its heartbeats are refused and its result is recorded as an authorization
  stop (on such a node, as an adapter failure). Update fleet nodes with the control plane.
- Hunt secret withholding covers the formats listed above; some free-text forms are still shown,
  for example `$db['default']['password'] = '…'`, an nginx `Authorization "Basic …"` line, a
  multi-line YAML flow sequence under a secret key, and a password in a URL path.
- Discovery admission records how a target was added; it is not an authentication boundary. Any
  caller of the target routes acts as the operator.
- `POST /hunts/{id}/query` is still called for viewers on the Hunt run page.
