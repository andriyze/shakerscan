# ShakerScan 2.12.1

**Status:** integration candidate on `release/2.12.1`; it follows 2.12.0.
The client for this release is `shakerscan` 0.12.0 (unchanged).

A patch release: the host target's finding count after device Scans, a session capabilities
answer the web UI reads to hide controls a person cannot use, clearer wording and naming across
the UI, and paged Investigation candidates. No schema changes; a rollback restores the pre-upgrade
database dump, as for every release (`docs/upgrade-and-rollback.md`).

## Fixes

- **A host target's finding count stays current after device Scans.** Device posture and device
  probe Scans stored their findings under the host target, but only the device profile's count was
  refreshed, so `targets.active_findings_count` (the Targets page badge) stayed stale until the next
  API start. The worker now recounts the host target in the same transaction, and the posture
  completion step recounts both.
- **A web app added on a known host keeps the name the person gives it.** The Add targets dialog
  now sends the display name with the web app too, and `POST /targets` with a name fills a target
  that has no name of its own. A chosen name is never replaced.
- **Advisory titles no longer end in "This issue affects undefined".** The record's generated
  sentence, which names no product, is dropped from advisory titles.

## Session capabilities

- **`GET /session/capabilities` (session-capabilities/v1, `docs/session-capabilities.md`).** The web
  UI asks once per page load which actions the signed-in person may use and hides controls that
  would only end in a refusal: adding targets, starting Scans (New Scan, Cancel, Scan again),
  target authorization and edits, Hunt permissions, Stop and saved actions, Retest, verdicts and
  Accept risk, bulk triage, record deletion (`records.delete`) and the discovered-secrets actions.
  A link to a refused page keeps its words without the link. The open-source engine has no roles
  and answers that every action is allowed; a server in front of the engine can answer for the
  person. Until the answer arrives, and on any failure or other schema, everything stays allowed.
  A refused answer is read to the end, so no request stays open.

## API

- **`GET /findings?include_retest=true`** adds `retest_supported`, `retest_type`, `retest_modes`,
  `retest_active` and `retest_unsupported_reason` to every row of the limit/offset list, decided as
  for `GET /findings/{id}`. Without the flag the list is unchanged.
- **`GET /investigation/candidates`** carries `target_name` and `target_url` on every row, `status`
  takes a comma-separated list, and `unversioned_advisories` (`include`, `exclude`, `only`) leaves
  out or counts the automatic advisory matches made without a known product version.
- **The discovered-secrets listing names targets.** `target_names` gives the name (else the address)
  of the target a secret was found on and of each target it is granted to. The Hunt planner's view
  does not carry them.

## Interface

- Investigation candidates load one page of 50 across the open statuses, grouped by target with
  its name, with Previous and Next; unversioned advisory matches are hidden by default behind a
  counted toggle.
- Discovered secrets: Grant offers a searchable target picker, the list is grouped by kind and
  field and paged, grants are listed by target name, and the terminal command offered for a
  step-up carries the chosen values, shell-quoted.
- Target pickers and the Schedules list lead with the target's name (or its host when the name is
  only the URL) and show the full URL underneath.
- A queued Scan lists the running Scans it waits behind; a refused New Scan shows its reason
  beside Run Scan and says when Scan slots are busy.
- A disabled Retest prints its reason as visible text, not only a tooltip.
- The Hunt page says whose decision a terminal permission request is, with a copyable
  `shakerscan approve` command; the capability-call card shows its limit in words.
- New Scan, credential and dashboard choices are worded plainly; build hashes and plan ids move
  into a collapsed Technical details section.
- The Dashboard says when its cohort filter hides the latest results and offers Show all cohorts.
- A cut domain group counts its subdomains the same way in every label.
- The Credentials list names a profile's owner by address, and a managed workspace shows one
  copyable Hunt command per target.
- A device page whose side request fails keeps the page and offers Retry for that part.
- The sidebar section switch is disabled until the page can act on a click.

## Known limits

- The session capabilities answer hides controls; it does not authorize anything. Every request is
  still decided by the server that receives it.
