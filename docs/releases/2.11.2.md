# ShakerScan 2.11.2

**Status:** in development.

A patch release: retest, replay and coverage correctness fixes. No schema changes.

## Security

- **A finding found signed in is never retested anonymously.** An authenticated Scan keeps only
  references to its credential profiles, so a retest of its findings had no identity and sent the
  proof's request anonymously. Where the application serves a guest page with HTTP 200, a verified
  SQL injection, NoSQL injection or browser XSS still exploitable for the signed-in user read as
  "likely fixed", and a linked Hunt investigation candidate was marked refuted. Such a retest now
  sends nothing and is inconclusive, with the reason, in every tier: the proof's own check, the
  older check ladder and the AI-driven tier. Run an authenticated Scan with the same profile to
  check the finding again.
- **A bare query token stays out of replay metadata.** A captured URL whose query is a bare
  token (`/items?<token>`, as share and signed links use) had the token removed from the replayed
  URL but kept as the name of the withheld parameter: in the capture's `captured_withheld` and
  `captured_query_parameters_withheld`, the replay plan and the receipt a Hunt's
  `collections.replay_safe` and `collections.replay_active` answer with. 2.11.1 said this was
  masked; only the URL was. The withheld parameter is now listed as `query:<redacted>`, and the
  replay plan masks a token-like name in every withheld label whatever produced it. A bare AWS
  access key id or standard base64 name is now withheld from the replayed URL as well (it was
  sent to the target), and HAR and Postman request lists mask a bare token name too. Receipts
  stored by 2.11.0 and 2.11.1 are unchanged and may still hold such a name.
