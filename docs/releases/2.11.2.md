# ShakerScan 2.11.2

**Status:** in development.

A patch release: retest, replay and coverage correctness fixes. No schema changes.

## Security

- **A finding found signed in is never retested anonymously.** An authenticated Scan keeps only
  references to its credential profiles, so a retest of its findings had no identity and sent the
  proof's request anonymously. Where the application serves a guest page with HTTP 200, a verified
  SQL injection, NoSQL injection or browser XSS still exploitable for the signed-in user read as
  "likely fixed", and a linked Hunt investigation candidate was marked refuted. Such a retest now
  sends nothing and is inconclusive, with the reason, in every tier: the proof's own check, the
  older check ladder and the AI-driven tier. Run an authenticated Scan with the same profile to
  check the finding again.
