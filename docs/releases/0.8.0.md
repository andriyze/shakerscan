# ShakerScan 0.8.0

ShakerScan 0.8.0 is a major trusted-operator release for web, API, AI-model, and distributed
security testing. It adds a complete Model Intake workflow, graduates the outbound-only HTTPS Fleet
broker, and strengthens proof, coverage, dependency, upgrade, installer, and release controls.

## Highlights

### One-link Model Intake

- Paste a Hugging Face repository link in the default UI workflow. ShakerScan resolves and pins an
  immutable revision, completely acquires the repository within explicit limits, hashes every
  member, derives runtime dependencies, and runs every applicable built-in check.
- Static review combines native format/archive/Python analysis with ModelScan, Fickling, Semgrep,
  Trivy, OSV-Scanner, and pip-audit. Results retain each tool's applicability, rules, coverage,
  findings, errors, and evidence rather than collapsing unavailable or incomplete checks into a
  pass.
- CycloneDX, SPDX, AIBOM, license inventory, and third-party-notice artifacts record completeness
  and provenance. The concise HTML report leads with the decision and a linked control table, then
  presents packages, licenses, vulnerabilities, scanner details, runtime behavior, and evidence.
- On supported AMD64 Linux/KVM hosts, the opt-in Firecracker runner loads and exercises fixed
  offline model profiles with no network interface, bounded resources, syscall/network-attempt
  telemetry, repeat inference, and signed evidence receipts. Eligible unsafe PyTorch weights can be
  converted to safetensors inside the microVM and checked for tensor and embedding equivalence.
- `PASS`, `BLOCK`, `INCOMPLETE`, and `REVIEW_REQUIRED` are deterministic technical outcomes. AI and
  callers cannot override required controls or turn missing evidence into approval. Human publisher
  trust, privacy, legal, production-signing, and deployed-data-plane decisions remain explicit
  follow-up where applicable.

### Multi-node Fleet over HTTPS

- A Linux control plane can coordinate digest-pinned workers on owned or customer-hosted Linux
  nodes through the supported outbound-only HTTPS broker. Remote nodes receive no Redis,
  PostgreSQL, or object-store credentials.
- Enrollment tokens are hashed at rest, transport-bound, expiring, bounded by use count, and
  revocable. Per-job leases support heartbeat, loss/reclaim, duplicate-result fencing, centralized
  artifacts, execution snapshots, and deterministic placement.
- The Fleet UI shows authoritative health, desired/actual capacity, drift, current work, lifecycle
  events, scaling, drain/resume, rollout, and revocation. Operator credentials remain browser-session
  only and unauthenticated views do not present fake empty fleet state.
- Built-in WireGuard remains preview code outside the 0.8.0 supported boundary until it passes its
  separate physical two-host acceptance matrix.

### Proof-first DAST and Continuous ASM

- Deterministic evidence—not AI opinion or labels—controls verified status and high-impact
  severity. Unproven or partial attack-chain steps cannot render as fully exploited.
- Execution receipts distinguish completed, skipped, blocked, cancelled, failed, partial, and
  unobserved work. Missing telemetry is never reported as clean coverage.
- Authenticated BOLA/IDOR requires accepted, distinct principals and a deterministic differential.
- Continuous ASM retains endpoint inventory, attempt-ledger coverage, gap analysis, bounded focused
  waves, and durable scheduling evidence.

### Deep Hunt and operator workflows

- Deep Hunt remains the canonical keyless, agent-guided investigation workflow. The coding agent
  plans bounded actions while ShakerScan enforces target scope, expiry, request and action budgets,
  provenance, and deterministic promotion.
- Findings, retests, Evidence, Exposure, Timeline, Campaigns, Exceptions, application graphs, and
  source-aware filters provide a consistent path from signal to proof and remediation.
- AI Gate remains a preview surface in this release.

### Installation, upgrades, and release engineering

- Clean installation and repeated dirty upgrades preserve database state, volumes, namespaced
  target identity, findings, configuration, and legacy Fleet credentials; required migrations fail
  closed.
- Locked Python and Node dependencies, packaged scanner self-tests, generated capability inventory,
  installer smoke tests, and candidate-image release gates reduce build drift.
- Release images are published separately for scanner/worker, API control plane, UI, and Model
  Intake signer on `linux/amd64` and `linux/arm64`. Only the API image contains the pinned Docker CLI
  needed for explicit Model Intake guest staging.

## Install

```bash
curl -fsSL https://install.shakerscan.com | sh
```

Then open [http://localhost:3000](http://localhost:3000), or start an agent inside the installed
runtime:

```bash
shakerscan agent codex
# or: shakerscan agent claude
# or: shakerscan agent opencode
```

## Upgrade from 0.5.7

Back up before upgrading:

```bash
shakerscan backup
curl -fsSL https://install.shakerscan.com | SHAKERSCAN_START=0 sh
shakerscan start
shakerscan status
```

After startup, verify the API, UI, worker build status, existing targets/findings, and one safe Quick
scan. Follow the complete [upgrade and rollback runbook](../upgrade-and-rollback.md).

- `shakerscan/shakerscan-scanner:0.8.0`
- `shakerscan/shakerscan-api:0.8.0`
- `shakerscan/shakerscan-ui:0.8.0`
- `shakerscan/shakerscan-model-intake-signer:0.8.0`
- Platforms: `linux/amd64`, `linux/arm64`

```bash
./scanner.sh start --prebuilt --image-tag 0.8.0
```

The API image is intentionally separate from the scanner/worker image. The shared scanner image
does not contain Docker tooling. Firecracker installation remains an explicit privileged host
operation and is never performed by the web API.

## Supported deployment boundary

ShakerScan 0.8.0 is a trusted-operator, self-hosted release. It does not provide ShakerScan login,
users, roles, tenant isolation, or comprehensive historical evidence-secret rewriting. Localhost is
the default. Keep remote deployments behind Tailscale, a VPN, firewall, or an authenticated reverse
proxy, and treat scan results, evidence, configuration, and backups as sensitive.

Fleet production support is limited to the outbound-only HTTPS broker. Model Intake's Firecracker
tier requires an explicitly installed AMD64 Linux/KVM runner; unsupported or incomplete runtime
evidence fails closed. AI Gate and Fleet WireGuard remain preview surfaces.

## Release validation

The release workflow publishes only from the exact `v0.8.0` commit reachable from `main` whose
generated documentation, locked builds, unit/contract suites, release gates, production dependency
audit, and UI build pass. Physical Model Intake, broker Fleet, installer, upgrade, browser, and
post-publish checks are tracked in the [release-readiness checklist](../release-readiness.md).
