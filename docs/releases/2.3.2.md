# ShakerScan 2.3.2

A maintenance release for self-hosted deployments. It fixes the crawler memory blow-up on
JavaScript-heavy sites, makes coverage truthful when a scanner dies, lets a target be authorized
once instead of per scan, and gives hardened deployments without the Docker socket honest
capacity and inventory. Upgrade in place from 2.3.1; 0.8.18 remains the oldest directly certified
upgrade base. No change to the deterministic proof boundary.

## Changes

### Crawler: bounded memory and truthful coverage

- The static crawler (`katana` 1.7.0) parses JavaScript with a fork of jsluice pinned to a March
  2026 snapshot of the pure-Go tree-sitter port whose string-literal lexing is super-linear. One
  inline script with a few thousand escaped quotes, which every Next.js page carries as its flight
  payload, took the crawler past 6 GiB in about 20 s and got it killed. The scanner image now
  builds katana against gotreesitter v0.52.0: the same crawl peaks at 599 MiB and finds 427
  endpoints where the old build emitted one line. Reported upstream (projectdiscovery/katana
  discussion 1840).
- The static crawler runs under a data-segment bound (`prlimit --data`, Linux; default 2 GiB,
  `SHAKERSCAN_CRAWLER_MEMORY_LIMIT_MB`, 0 disables), so a future parser regression ends with Go's
  own out-of-memory error at the bound instead of taking the worker container to its cgroup limit.
  The headless crawler is not bounded because Chromium inherits the limit.
- A scanner that emitted output and then exited non-zero or by signal (the kernel's OOM kill, the
  crawler's memory bound) is recorded as `partial` with `exit_<code>` or
  `crawler_memory_bound_exceeded`, never as complete. A required action that ends partial, timed
  out, failed or blocked makes the scan's top-level coverage `partial` with
  `<capability>_<status>[:<reason>]` among the reasons.

### Authorize a target once

- Active testing still requires a target-bound approval receipt, but the receipt is now the
  target's standing authorization: `POST /targets/{id}/authorization` records it once (tier
  `active` or `intrusive`, `approved_by` recorded, no expiry), `GET` reads it, `DELETE` revokes
  it, and `TargetCreate.authorized_by` records it at creation. Target lists carry
  `authorized_for_active_testing`.
- A scan submitted with `policy.active_testing` and no receipt resolves the target's standing
  authorization; a privileged Hunt start does the same and treats it as the confirmed
  authorization. The authorization ends by revocation or when the target's scope changes to
  another host. Credential use keeps its explicit credential-tier receipt; the dangerous tier
  keeps bounded per-action approvals.
- The UI offers "I own or am authorized to test this target" when a target is added, shows each
  root target's authorization with authorize and revoke actions, and no longer mints a two-hour
  receipt per active scan.

### Deployments without the Docker socket

- `SHAKERSCAN_PRIVATE_NETWORK_TARGETS=allow` (default `refuse`) admits loopback, private and
  reserved addresses for every environment, recorded on every scope receipt as
  `allowed_by_deployment_policy`; link-local, multicast and unspecified addresses stay refused.
- `SHAKERSCAN_FLEET_MEMORY_GB` declares the fleet memory when Docker's `/info` is unreachable, so
  the active-scan cap no longer falls back silently to five. `/health` reports
  `capacity` (effective cap and its source) and `deployment_policy`.
- The worker inventory no longer turns an unknown local container count into "expected 0": fresh
  build reports are the authority when no inventory exists, and `worker_build.inventory` says
  whether `docker` or `reports` applied. A healthy hardened deployment stops showing "Workers
  mixed/stale".
- The API and every worker fail fast with the cause and remedy named when the engine database
  has no schema (an unreadable `db/init.sql` at first start), instead of crash-looping on
  `relation "scans" does not exist`.

### UI

- The sidebar shows the edition named by a managed deployment's capability manifest instead of a
  fixed "Open Source Edition" label; standalone installs are unchanged.

### Release and CI hygiene

- The Model Intake signer image applies Debian's security fixes at build time, so a published fix
  for an OS package no longer fails the image gate for every pull request.

## Upgrade

Upgrade in place from 2.3.1. The stable installer channel advances only after publication and public
smoke. Existing approval receipts stay valid; targets gain a standing authorization the first time
an operator authorizes them. No destructive migration.
