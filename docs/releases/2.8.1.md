# ShakerScan 2.8.1

**Status:** candidate prepared 2026-10-09. Publication and stable-channel promotion are pending.

This patch release brings the changes merged since 2.8.0 (#366–#370, #372, #375–#377 and
#379–#381): a revoked or expired
authorization now stops a running local web scan, Hunt grant revocation rebuilds authority from the
grants that are still live (a P1 from the external release audit), the subdomain discovery scope
boundary is fixed and gains wildcard DNS detection and takeover checks, slow SQLi candidates get an
explicit budget verdict, and client 0.8.1 fixes the terminal Hunt experience. It also fixes an
installer start failure and rebuilds the Go tools against patched toolchains.

An external review found further issues that are fixed in 2.8.2, not in this release: Hunt secret
masking (N56), the audit's R2 and R3 findings, scope and public-suffix hardening, and a
long-standing issue where masked HTTP archive exports kept the raw response body's SHA-256, which
could let a low-entropy secret in that body be guessed offline. The last issue is present in
earlier releases too. See Known limitations.

## Upgrade notes

- **A scan stops when its authority ends.** A running local web Scan now re-checks its authorization
  before every action and polls it while an action runs. Revoking the target's authorization stops
  the Scan at its next action and interrupts the current one within seconds. A Scan admitted on a
  bounded approval now stops when that approval reaches its `expires_at`; in 2.8.0 it ran to
  completion. The report is finalized from what ran, with coverage `partial` and
  `stop_reason: authorization_withdrawn`. A passive-only Scan with no approval receipt keeps running
  after a revoke, as before. An unreachable database is reported as `authorization_unverified`, never
  as a revoke; an action is interrupted only after about 10 s of continuous outage. (#379)
- **Revoked Hunt grants stay revoked.** In 2.8.0, revoking one permission grant restored the policy
  recorded by another, which could turn state-changing HTTP back on after every write grant was
  revoked. Authority is now the Hunt's baseline plus every live grant, rebuilt on each grant and
  revoke. A revoke also beats the Hunt's `--allow` pre-authorization: the start bounds stop
  auto-granting what a revoked grant covered for the rest of the Hunt, and the next refusal waits
  for a person's `shakerscan approve`. At startup, unfinished Hunts that 2.8.0 granted something are
  repaired once; a Hunt that cannot be rebuilt is cancelled with
  `permission_authority_unrepaired`. (#372)
- **Subfinder provider keys.** Subfinder runs with `-all`. Provider keys can be supplied inline with
  `SHAKERSCAN_SUBFINDER_PROVIDERS` or as a read-only mounted YAML file named by
  `SHAKERSCAN_SUBFINDER_PROVIDER_CONFIG`. Keys are written to a private per-run file and never appear
  in arguments, logs or receipts. Fleet nodes receive inline keys in the connection bundle at
  `fleet init`; rotating them needs re-enrollment or a `worker.env` edit. An invalid configuration
  is reported with a fixed error code and the run continues without keys. (#377)
- **Installer group fix.** A non-root install whose primary group owns the Docker socket no longer
  fails to start with `group_add items at 0 and 1 are equal`. The launcher writes the new
  `SHAKERSCAN_API_SANDBOX_GROUP_GID` key to `.env`, and a Compose configuration error is now reported
  as such instead of as an image pull or network problem. (#366)

## Scans

- **Discovery scope.** Discovered names are accepted only on a DNS label boundary, so
  `notexample.com` can no longer become a target under `example.com`. Every discovery source and
  insert path uses one canonicaliser. (#377)
- **Wildcard DNS.** Before recording names, discovery probes random labels under the apex and its
  parents. A name whose answer is the wildcard's, and that no certificate source names, is
  suppressed but still listed; the Scan reports the `wildcard_dns` partial reason. (#377)
- **Subdomain takeover.** A new `subdomains.takeover_check` capability runs after subdomain
  discovery. Discovered names get DNS evidence only; only the Scan's bound host receives one
  same-origin `GET /`. A takeover is verified only for a service rated "vulnerable": an
  NXDOMAIN-signature terminal confirmed by an independent DoH resolver, or the bound host's HTTP
  fingerprint. DoH confirmation is used only for catalogue service names and only where the binding
  permits DoH. Edge-case services (GitHub Pages, Heroku, Shopify, Tumblr) and other dangling
  terminals are suspected at most, and HTTP-signature services on discovered names are
  `inconclusive_dns_only`. Nothing is claimed or changed. (#377)
- **SQLi budget verdicts.** Stage costs count each tested body field, and a multi-field body is
  verified one field per run with its own checkpoint. A continuation is funded only when the
  candidate's own measured rate predicts it can settle the next unit. Verdicts are per technique: a
  technique whose next unit no round, or the candidate's part of the Scan's residual, can fund is
  reported inconclusive for budget (`sqli_budget_inconclusive`), while the candidate's other
  techniques keep running; a candidate still waiting when the Scan ends is reported inconclusive for
  an exhausted budget. Fast does not continue slow request-body SQLi techniques whose next unit
  needs more than one 375-second round; use Balanced, Thorough or Hunt for slow request bodies. The
  continuation residual is shared between the verifier lanes rather than taken by SQLi first. No
  technique is dropped from the order. (#367)
- **Release gate.** The deployment decision counts every blocker, identifies each row and attributes
  Hunt findings to Hunts; a truncated active set fails closed to `needs_review`. (#368)
- **Targets and exports.** The Targets list reads authorization from the authority the Scan path
  resolves, including web apps that carry their own receipt. "Requests JSON" exports every matching
  call (up to 20,000) instead of the first page. DNS SOA timers are no longer masked as secrets.
  (#368)

## Hunt and client 0.8.1

- `hunt permissions wait` and the MCP wait tool poll at most once per second instead of flooding
  the engine in the last second. (#369)
- `approve --watch` keeps polling while it prompts, decides only on a single fresh lowercase key, and
  ignores arrow keys, Alt keys, pastes and terminal control strings (OSC, DCS, APC, PM, SOS and 8-bit
  CSI). Ctrl-C, SIGTERM and SIGHUP restore the terminal and revoke an Enterprise approver session.
  (#369, #375)
- Re-running `shakerscan agent` merges only the keys the client owns in `opencode.json`, `.mcp.json`
  and `.claude/settings.json`, keeps everything else, never writes through a symbolic or hard link,
  and reports agent settings that changed since the last launch. (#369)
- The client keeps workspace records under `${XDG_STATE_HOME:-~/.local/state}/shakerscan/` and the
  default agent workspace under `${XDG_DATA_HOME:-~/.local/share}/shakerscan/agent`, moving existing
  ones once. (#375)
- `/hunts/contract` publishes each capability's input fields, and the MCP capability tool names them
  with an example; refused inputs say what is required. (#369)
- The Hunt run page no longer makes launcher reads that a viewer is refused. (#368)

## Images and installer

- The scanner and Model Intake Go tools are built with Go 1.27.2 and 1.26.9 and
  `golang.org/x/net` v0.60.0, fixing CVE-2026-78667, CVE-2026-78669 and CVE-2026-97031 without
  waivers. (#370, #376, #381)

## Known limitations

- Only the canonical web Scan on the local worker, including its parallel shards, is re-checked
  while it runs. Device posture, probe and web-DAST scans, AI scans, finding retests and broker
  actions already running on a fleet node still rely on the authorization checked when they were
  admitted or leased; re-checking them is planned for 2.8.2. If the authorization check's database
  call itself hangs, the action in flight is not interrupted until that call returns (fixed in
  2.8.2). Revoking a target's authorization revokes only standing receipts; a Scan admitted on an
  explicit bounded approval runs until that approval expires or is revoked. (#379)
- An `oob` or `tcp-discovery` auto-grant can still turn `active_testing` on after a revoke. Revoking
  Hunt grants leaves the bound target authorization in place. (#372)
- Fixed in 2.8.2, not here: Hunt secret masking (N56), the external audit's R2 and R3 findings,
  scope and public-suffix hardening, and masked HTTP archive exports that still carry the raw
  response body's SHA-256 (present since earlier releases; a low-entropy secret in such a body could
  be guessed offline from the digest).
- `POST /hunts/{id}/query` is still called for viewers on the Hunt run page; gating it needs a
  role-scoped feature from the gateway. (#368)
