# ShakerScan 2.4.1

Fixes found by driving an open-source engine from the client over a LAN, each reproduced live and
retested from a second machine: a target on a non-standard port could not exist, a scanned or
hunted target could not be deleted, and a Hunt asked for active work on an unauthorized target
answered with a refusal nobody could act on. Upgrade in place from 2.4.0; the target-identity
change runs a recorded one-time key recompute at startup. No change to the deterministic proof
boundary.

## Changes

### Targets: a non-default port is part of the identity (#187)

- Web identity was host-only, so `https://host:8443` deduped into the `https://host` row, every
  scan and Hunt kept going to the closed default port, and recreating the target with the port
  answered `already_exists`. The canonical key now keeps a port that is not the scheme's default;
  http and https on the default ports still merge into one asset. The Python key and the SQL
  trigger agree, and a recorded startup migration recomputes existing keys (they can only split).

### Deletion works after scans and Hunts (#185, #187)

- Every recorded HTTP transaction is classified `sensitive` by default, and the deletion inventory
  treated that as a hold: any target that had ever been scanned or hunted answered "legal hold or
  protected evidence blocks deletion; archive the target instead". Sensitive is a classification;
  only `legal_hold`/`audit` classes and explicit hold flags block erasure.
- Abandoned work no longer blocks deletion forever. Work a worker is actively updating still
  blocks, and the message names the rows and the cancel route; rows never picked up or untouched
  for 15 minutes are reported as `abandoned` in the preview and cancelled by the approved
  deletion, which also stops the target's automatic work (ASM, schedules).
- Cancelling a scan settles its ASM campaign; a campaign with no unfinished scan is done. Before,
  a cancelled scan left its campaign `active` and the target read as having running work.
- Archived targets stay reachable: the Targets page has a "Show archived" toggle, an archived
  badge, a Restore action, and the delete dialog no longer offers "archive instead" for a row that
  already is.
- Agents get a guarded `/delete-target` command: archive, restore, preview, the exact dangerous
  approval body, execute, and the rules (explicit user request, show the preview, never batch).

### Hunt (#184)

- A Hunt asked for active, state-changing or network-discovery work on a target with no standing
  authorization is refused with a message that names the remedy
  (`POST /targets/{target_id}/authorization`); the MCP `shakerscan_hunt_start` policy schema says
  the same up front. The gate itself is unchanged.

### Launcher (#187)

- `rebuild` right after `install-deps` in the same shell built the scanner image and then failed
  to resolve it: Compose had gone through sudo while the plain `docker image inspect` was refused
  at the socket. The resolve now follows Compose's choice.

### Client

- Client 0.7.0 carries the updated agent kit (the `/delete-target` command and the Hunt
  authorization guidance) and everything from 0.5.0 and 0.6.0: `agent --url` and
  `connect http://<engine>:8080` for an open-source engine on a trusted LAN.
