# ShakerScan 2.8.3

**Status:** candidate prepared 2026-10-10. Publication and stable-channel promotion are pending.

This is a fixes-only patch release for defects found in the release acceptance of 2.8.2. 2.8.2 was
published but not promoted to the stable channel, so an install that follows the stable channel
moves from 2.8.1 to 2.8.3. Client 0.8.3 ships with it.

## Upgrade notes

- **2.8.2 migrations now reach upgraded installs.** 2.8.2 added `discovery_runs.requested_by`, the
  one-time public-suffix `root_domain` recompute and the target host spelling repair to a startup
  step that an already-converted database skips. On an install upgraded to 2.8.2, every admitted
  `POST /discovery` (the Targets page's "Discover subdomains") failed with 500, and the recompute
  and repair never ran. 2.8.3 applies all three at startup on every database. Each one runs only
  once or changes nothing when repeated. A fresh 2.8.2 install already had them.
- **What the recompute and repair change on first start.** These are the 2.8.2 upgrade notes.
  On an install upgraded to 2.8.2, they take effect when it starts 2.8.3. On an install still on
  2.8.1, they take effect when it moves to 2.8.3.
  - A target stored under a public-suffix `root_domain` (`co.uk` for `shop.example.co.uk`) gets the
    root its URL has now.
  - A target whose host was stored as a numeric spelling with one reading (`127.1`, `0x7f.0.0.1`)
    is rewritten to dotted-decimal and must be authorized again.
  - Any other host the canonicalizer refuses is flagged with `host_canonicalization_review`.
- **Rolling back to 2.8.3 from a later release.** 2.8.3 reads target instructions that a later
  engine wrote with an instruction authority or origin that 2.8.3 does not know. 2.8.2 answered 500
  on `GET /targets/{id}/skill` for such a target. An unknown authority reads as `none`, and text
  marked with any origin other than an operator's is advisory, never operator guidance.
- **Rollback.** A database that 2.8.3 started can run 2.8.2 again: the added column is nullable,
  and the rewritten roots and hosts are the ones 2.8.2 itself writes. It can also run 2.8.1, which
  ignores the column and accepts the canonical hosts. The host spelling repair runs once per
  database, so a numeric-spelled target added after rolling back to 2.8.1 is not repaired when
  2.8.3 starts again; add it again with its dotted-decimal address.

## Hunt secret withholding

- **Separators.** A secret that contains `&`, a quote or `<` is now withheld whole: in the planner
  view, in `artifact.inspect`, `http.request` and HTTP-experiment observations, and in masked
  JSON/HAR exports.
  - In 2.8.2, an assignment at the start of a line (`.env`, `.ini`, `php -i` output) ended its value
    at the first `&`. A Django `SECRET_KEY` therefore showed as `[withheld:1]&<tail>`, with the tail
    in clear text.
  - A line value now runs to the end of its line, at any length. A trailing `)` stays part of it.
    As in a dotenv file, a blank followed by `#` or `;` still starts a comment.
  - A quoted line value runs to its closing quote. An escaped `\"` does not end it, and a dotenv
    value in double quotes may span lines when its closing quote ends a line.
- **Connection strings.** These were cut the same way.
  - A `key=value` pair after `;` runs to the next `;`. A quoted one runs to its closing quote, and
    a doubled quote inside it is one quote.
  - A connection string in a markup attribute (`web.config` `connectionString="…;Password=…;"`) is
    decoded first, so `&amp;` inside a password is part of it.
  - Mid-line query parameters (`?token=…&next=…`) keep `&` as their separator.
- **`php -i` output.** Lines such as `DB_PASSWORD => …` are now recognized. 2.8.2 showed these
  values. Only a line that starts with an environment-style or dotted directive name counts, and a
  value that reads as code does not: JavaScript arrow functions and PHP array entries stay visible.
- **Long values.** An inline value longer than 512 characters is withheld whole. Before, it was
  cut at that length.
- **References.** The reference binds the complete value, so a Hunt that sends it back sends the real
  secret.

## Connected devices

- **Revoke stops list-dialog scans.** A device scan started from the `/devices` list stops when the
  device's authorization is revoked.
  - The list's Scan dialog confirms authorization for each scan. The scan route then did not bind
    the device's standing authorization, so the run had nothing to re-check, and "Revoke
    authorization" did not stop it. The device page already bound it.
  - Both routes (posture scans and service probes) now bind the standing authorization whenever the
    device has one, whatever the confirmation.
  - The device Hunt tools go through the same routes.
  - A device without a standing authorization still scans on the per-scan confirmation. As before,
    such a scan is not re-checked while it runs.
  - A scan bound to the standing authorization depends on that exact authorization, as scans from
    the device page already did. Renewing or re-issuing it fails a queued scan of that device at
    dispatch and stops a running one, even one started with the per-scan confirmation.

## API

- **CLI findings.** `GET /api/v1/findings?scan_id=…`, the route behind the installed CLI's findings
  command, returned 500 in 2.8.1 and 2.8.2. It now lists the Scan's findings again.
- **Arsenal evidence lists.** The Arsenal command that lists evidence instances returned summaries
  instead of full rows. It now returns full rows, as `GET /evidence/instances` does by default.

## Client 0.8.3

- **State directory mode.** Starting the agent now tightens to `0700` a state directory
  (`~/.local/state/shakerscan`) that an earlier client or a umask left open to other users, along
  with its workspace records directory. A directory owned by another user is left unchanged.

## Known limitations

These are carried from 2.8.2:

- **Retests.** Finding retests are checked only when they are admitted, not while they run.
- **AI target scans.** An AI target scan stopped for authorization does not keep the findings it
  made before the stop.
- **Older fleet nodes.** A fleet node on an older image does not ask the control plane while an
  action runs. Update fleet nodes with the control plane.
- **Hunt secret withholding.** It still does not cover some free-text forms:
  - `$db['default']['password'] = '…'`;
  - an nginx `Authorization "Basic …"` line;
  - a multi-line YAML flow sequence under a secret key;
  - a password in a URL path;
  - a shell value built by quote concatenation (`KEY='a'\''b'`);
  - an OAuth `code=` parameter in a link inside a response body. Redirect `Location` headers are
    covered;
  - a value whose start is a value withheld earlier in the Hunt (`API_KEY=<that value>&tail`);
  - a quoted secret quoted again inside prose (`"use the api_key: 'abc&def'"`);
  - a phpinfo-style table cell whose value sits in `<pre>`.
- **Over-masking.** A `;`-separated value outside a connection string (a cookie list, a URL
  matrix parameter) runs to the next `;`, so text after it on the same line can be withheld
  with it.
- **Masked archive exports.** These still show withheld values as `***`, not as `[withheld:n]`
  references. Only the planner view shows references.
- **Discovery admission.** It records how a target was added, for admission only. It is not an
  authentication boundary.
