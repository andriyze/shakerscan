# ShakerScan 2.0.0

ShakerScan 2.0.0 is the AI-native architecture release. It replaces the historical family of Scan
engines with one deterministic Scan contract and one target-kind-aware Hunt runtime. Budget
profiles are ceilings, active testing is an explicit permission, and verified findings remain
deterministic proof decisions rather than AI claims.

This file prepares the release candidate. It is not a publication receipt: the final source SHA,
image digests, signed provenance, exact-SHA E2E runs, public-install smoke, and stable-channel
promotion remain pending. The stable installer continues to resolve 0.8.18 until those gates pass.

The candidate gate also requires exact-SHA CodeQL, real-fleet Scan parity, a real Hugging Face review
through Firecracker/KVM, an authorized physical-device posture scan, and high/critical vulnerability
scans of all four final image manifests. These are pending operational receipts, not claims made by
this source change.

## Highlights

- One canonical deterministic Scan execution plan is shared by local, broker, and parallel workers.
  Immutable plan revisions, target bindings, hard multi-dimensional reservations, action-level
  resume, cancellation authority, and receipt-backed evidence are enforced server-side.
- One canonical Hunt runtime serves Web, API, network, and connected-device investigations. The
  coding-agent session chooses strategy only from the server-returned capability manifest; target
  kind filters capability and safety policy instead of selecting another engine.
- Credentials and request collections are exact-target, encrypted, metadata-only public objects.
  Scan and Hunt queue only opaque profile/selection identifiers; workers decrypt only after target,
  approval, capability, and scope validation.
- Connected Devices is a separate product namespace with opt-in workers, positive reachability
  preflight, bounded TCP/UDP inventory, service/version/CPE evidence, request-aware web/API checks,
  SSH posture, policy controls, and the same canonical Hunt semantics.
- Evidence, Timeline, Campaigns, Exposure, Continuous ASM, Application Graph, AI Gate, Model Intake,
  Interactive Testing, Exceptions, Policy Profiles, Command Arsenal, and AI Ops Router are integrated
  around durable target, action, receipt, and proof records.
- Historical compatibility rows remain readable, but removed V1 write routes, legacy Scan command
  names, planner-supplied argv, and caller-supplied execution identities cannot create new work.
- The CLI and MCP adapter cover target inspection, findings, evidence, credentials, collections,
  Scan, and bounded Hunt workflows. MCP separates read-only Arsenal inspection from state-changing,
  target-bound Hunt V2 tools and never exposes reusable secrets, target overrides, argv, or shell.

## Safety and support boundary

- ShakerScan is a trusted-operator, self-hosted scanner. Localhost remains the default; remote access
  must stay behind a VPN, firewall, Tailscale, or an authenticated reverse proxy.
- Active DAST, device scanning, and Hunt execution require ownership or explicit authorization for
  the exact target. Silence and missing telemetry are inconclusive, never a clean result.
- The outbound-only HTTPS broker is the supported Fleet transport. WireGuard remains an operator
  preview outside the 2.0.0 production boundary pending separate physical acceptance.
- Model Intake deterministic review and report generation are release-gated. Firecracker remains an
  opt-in AMD64 Linux/KVM tier and fails closed when the host or evidence is incomplete.
- AI Gate remains a preview surface. AI can create notes and evidence-backed candidates, but cannot
  mark a finding verified or promote high-impact severity without a deterministic proof contract.

## Upgrade notes

- Back up the stateful installation before changing versions and follow
  [`docs/upgrade-and-rollback.md`](../upgrade-and-rollback.md).
- V2 migrations preserve targets, scans, findings, policies, credentials, collections, evidence,
  Fleet identity, and readable historical Scan labels. Startup fails closed on a required-schema or
  build-identity mismatch.
- Removed `scan-full`, `scan-smart`, and `--type` command surfaces are not installed. Use one Scan
  with `fast`, `balanced`, or `thorough` ceilings and explicit policy permissions.
