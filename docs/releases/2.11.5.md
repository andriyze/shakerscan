# ShakerScan 2.11.5

**Status:** integration candidate on `release/2.11.5`; it follows 2.11.4.

A patch release for Hunt. No schema changes; a rollback restores the pre-upgrade database dump, as
for every release (`docs/upgrade-and-rollback.md`).

## Hunt

- **A Hunt's own login is reusable.** A response capture of a header now reads any response that
  carries it, a redirect included: a form login that answers 302/303 with its session cookie was
  refused before (`http_workflow_capture_incomplete`), and the whole request was marked failed, so
  it could not be cited as evidence either. A capture of `Set-Cookie` holds every cookie the
  response set as `name=value` pairs (attributes dropped, deleted cookies left out), ready for a
  later request's `Cookie` header: bind it with `request_bindings`
  (`{"source_action_id": ..., "capture_name": ..., "header": "Cookie"}`). The value stays in the
  worker, sealed on the Hunt's action like every capture; the planner gets a reference, and every
  echo of the cookie in a response is withheld. A request bound to a session cookie keeps its
  response readable; one bound to another capture, to a credential field, or to a cookie value
  under eight characters is still reduced to its status, as before.
- **A capture the response does not carry no longer fails the request.** A failed login is a
  result: the request is recorded as completed, and the observation lists the missing capture in
  `captures_missing`. The other captures of the same request are kept.
- **The answer to a request that captures values shows the response's cookie names and security
  attributes** (`set_cookie_metadata`: `secure`, `httponly`, `samesite`), never their values.
- **The planner sees the page.** The body sample of an HTTP answer is cut from the first byte, and
  many applications open every page with kilobytes of inline CSS. An HTML answer in a Hunt now also
  carries `html`: the page's title, its links (`href`/`src`/`action`, same-origin first as paths,
  at most 40), its forms (method, action, field names and types; a hidden field's value only
  through the masking, which withholds a secret-named or credential-shaped one behind a reference;
  never a password field's value) and its visible text without `<style>`/`<script>` (at most 1,200
  characters). The body sample itself is unchanged.
- **`artifact.inspect` reads a signed-in page.** It takes `session_ref`, `as_principal`, or
  `request_bindings` with a captured session cookie (a `Set-Cookie` capture whose values are at
  least eight characters; other captures stay with `http.request`), under the same rules as
  `http.request`: a
  session or principal needs the Hunt's approval and credential allowance, a cookie binding needs
  active testing and is metered as an active action. A read with an identity does not follow a
  redirect to another origin.
- **Smaller capability answers over MCP.** The compact view of a Hunt capability answer drops the
  copy of the observations in `result.receipt.observations` (the same list as
  `action_result.observations`), as it already did for `result.observations`. The full view is
  unchanged.
- The Hunt skill has a short "log in, then reuse the session" recipe.
