# ShakerScan 2.3.1

A maintenance release. It corrects sensitive-exposure over-promotion, adds non-destructive data
retention and archive controls, and hardens release evidence. Upgrade in place from 2.3.0; 0.8.18 is
the oldest directly certified upgrade base. No change to the deterministic proof boundary.

## Changes

### Sensitive exposure: reachability is not confidentiality

- Reaching a file — including through a browsable directory listing or a well-known location such as
  RFC 9116 `/.well-known/security.txt` — is recorded as an observation (`listed_file`), not a
  verified confidential exposure. Only the existing content-specific secret contracts (private key,
  cloud credential, environment secret) promote to a proven sensitive finding.
- Directory-listing, metrics, actuator, and API-spec observations are reported at informational
  severity; actuator detection now keys on the Spring vendor media type instead of generic
  `_links`/`status` shapes. Location alone never establishes sensitivity, on any target.

### Data lifecycle: retention, portability, and archive

- A target can be archived without erasing history or cancelling admitted execution: it is
  deactivated, ASM is disabled, and future scheduled dispatch is paused under a row lock — a
  non-destructive alternative to deletion.
- Evidence deletion preserves sensitive history with the original ownership receipts, uses
  table-specific terminal-status contracts, and replays already-completed deletions before acquiring
  writer locks so concurrent retries stay consistent. Backed by real-PostgreSQL acceptance.
- Request-collection uploads retry atomically; a partial upload cannot leave a half-written
  collection.

### Release and CI hygiene

- The offline E2E-debt summary rejects incomplete or malformed scorecards (unnamed or duplicated
  areas and assertions, or an upstream area gate that did not pass) and reports executed versus
  required checks, so accepted debt can never hide missing evidence.
- The installer ships every module its runtime imports; the sensitive-exposure module is now part of
  the shipped import closure.

## Upgrade

Upgrade in place from 2.3.0. The stable installer channel advances only after publication and public
smoke. No capability-authority change; no destructive migration.
