# ShakerScan 2.5.6

This release fixes defects found while validating an HTTP LAN deployment on EC2, makes deployment
decisions and TLS coverage honest for re-observed findings and dual-stack targets, and adds
operator-authorized Hunt workflow writes, Pi as a supported coding agent, and public-repository
hardening. It ships with client 0.7.4.

## Scan, gate and reporting

- Deployment decisions match a scan's report findings to persisted rows by the canonical finding
  fingerprint. An earlier scan whose rows a later scan re-observed no longer double-counts blockers,
  and a policy exception recorded on a persisted finding now covers the scan that reported it. (#261)
- Receipt-backed V2 exposure proof is retained on persisted findings, and asset proof counts use the
  finding view's deterministic projection, including after an inconclusive retest. (#261)
- Scan reports distinguish selected check families from families that obtained testable candidates,
  and name selected active families with no candidates as coverage gaps. (#261)
- TLS inspection no longer reports dual-stack targets as partial because the worker has no IPv6
  route. Addresses the worker cannot originate are recorded as not examined and listed under
  `result.tls.unexamined_addresses`; a remote unreachable answer remains a failure. (#261)
- Batched SQLi/XSS verification keeps its traffic inside its request reservation. Attempts that
  previously overran the pinned connection ceiling and failed as `adapter_failed` now report
  `timed_out` with their measured use. (#261)
- Operator Scans are never throttled by the Continuous ASM per-domain quota. (#242)
- The dashboard's latest target results exclude cancelled scans. (#261)

## Hunt, client and operator flow

- Hunt supports operator-authorized HTTP workflow writes and active collection replay under the
  existing target binding, standing authorization, policy and budgets. (#241)
- `shakerscan scan`, `hunt` and `api` forward options placed before the target; `--` is no longer
  required. (client 0.7.4, #261)
- Private-network refusals name the environment a target is evaluated under and explain that a
  private address or an `internal` cohort does not make it a Lab target. The verdict is unchanged. (#261)
- Hunt budget amendments and Model Intake promotion keys work on plain-HTTP LAN origins without
  `crypto.randomUUID`. (#261)
- `shakerscan agent pi` launches Pi with the ShakerScan skills and runtime environment. (#245)
- `shakerscan stop` and upgrade no longer leave containers attached to the project networks. (#240)

## Security and repository

- Semgrep triage hardening, including AI Gate connectivity and MCP readiness checks that no longer
  follow redirects off the configured origin. (#244)
- Public-repository hardening: fixture data scrub, security fixes, licensing and community files. (#243)

## Known limits

- SQLi verification on remote, high-latency targets can still time out within a batch slice; those
  candidates are reported as timed out rather than verified or clean.
- The authenticated crAPI benchmark remains at 0/4 strict recall (no BOLA or SQLi candidates from
  its small endpoint set); the benchmark gate reports it as failed.

## Validation

Release-candidate certification, published-version smoke, and stable-channel promotion are required
before 2.5.6 is public.
