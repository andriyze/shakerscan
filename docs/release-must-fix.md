# Must-Fix Before the Next Release

**Status:** stop-ship checklist, reconciled 2026-07-20 against `6a089bf` and the
post-`f27bbff` audit. ShakerScan is **not release-ready** while any item below is open.

This is the short release-owner view, not a second implementation roadmap. Detailed ownership and
evidence remain in [`release-readiness.md`](release-readiness.md) and
[`proposed-next-steps.md`](proposed-next-steps.md). Items intentionally omitted here may still be
valuable, but they are not part of this minimum go/no-go set.

## Go/No-Go Rule

Release is allowed only when all nine rows have one of these dispositions:

1. **Fixed and evidenced on the frozen candidate**, with the artifact or workflow run linked from
   `release-readiness.md`; or
2. **Explicitly accepted by the release owner** with a written rationale, compensating control, owner,
   and expiry. REL-01, REL-02, REL-05, a known high/critical production dependency vulnerability, and
   stale/non-current validation evidence should not be waived for a major release.

Any code change after candidate validation invalidates the candidate evidence and requires the
affected gates to be rerun. Image rebuilds must retain the source SHA and record new image digests.

## Deliberately Not Stop-Ship

The following audited gaps should stay on the roadmap but should not delay this release unless the
release scope claims them: multi-node fleet support, the proposed Smart shared phase allocator,
additional focused SSRF/LFI/RCE/business-logic registry adapters, full Sigstore/cosign support for
every model registry, a built-in AV/YARA engine, live MCP invocation fuzzing, and broader AI/DAST
coverage improvements. Release notes must not imply these capabilities are present.
